# 遥测测试

验证多触发提交、心跳在线、会话采集、草稿恢复、双端队列、上传身份、扣点覆盖与接收端入库。字段以[契约](../contract.md)和[会话记录](../telemetry/schema.md)为准。

## 自动测试分工

| 入口 | 职责 |
|---|---|
| `npm run test:telemetry --prefix agent` | 统计、环境、凭据、扣点、草稿、队列、跨进程持久化、TLS 和禁用行为 |
| `npm run test:telemetry:e2e --prefix agent` | 真实 Pi、模拟 OA 与模型、两个真实 Go 接收端的上传和补发链路 |
| `cstoa-api-fastapi` 的 Agent 相关测试 | 请求 ID 透传、账单精确查询、成员与密钥归属、撤销和过期 |
| `cst-pilot-server/src` 的 Go 测试 | 鉴权、去重、迁移、可空派生列、每日汇总、CSV 与保留期 |
| `cst-pilot-server/scripts` 的 Python 测试 | SQLite 备份与恢复工具 |

跨仓库集成需先构建本机 Go 接收端，再从 Pilot 仓库根目录执行：

```powershell
$env:CST_TELEMETRY_RECEIVER = '接收端可执行文件的绝对路径'
$env:CST_WEB_TEST_TMPDIR = '本机临时盘目录'
npm run test:telemetry:e2e --prefix agent
```

未配置接收端可执行文件时，该项跳过。常规自动测试不访问生产接收端。

## 核对项目

| 范围 | 判定 |
|---|---|
| 会话统计 | 提问、模型往返、工具调用和时间与原始事件一致；未完成轮次的 usage 保留不完整标记 |
| CSTOA 扣点 | 请求尝试、已确认数与额度点成对核对；覆盖缺失、延迟、重试、中断、未知和真实零值 |
| 账单归属 | 只查本人请求；APIKEY 同时限定令牌，查询期间凭据变化不返回账单 |
| 回答结束 | 工具连续调用、自动重试和排队续答完成后，`agent_settled` 提交全部字段；多次提问不要求对应多次结束事件 |
| 事件字段 | 按 Pilot 实际依赖核对字段；SDK 的 `willRetry` 不当作扩展字段；成功、失败、取消分别验证 |
| 草稿与快照 | 回答结束、定时检查或关闭先持久化再上传，实例仍可继续提问；后续事件不修改已冻结快照 |
| 心跳调度 | 30 秒检查变化并发送在线状态；长任务和空闲均运行，多会话和重载只维护一组任务，纯心跳不增加用量或触发查账 |
| 在线判定 | 服务端时间超过 90 秒标记失联，15 秒周期检查；重复、倒序或无效心跳不延期，不生成 crash 或额外时长 |
| 恢复在线 | 唤醒或网络恢复后发送当前状态，历史统计补发不把原运行实例重新标记为在线；接收端重启可重判超时 |
| 协议能力 | 纯心跳与统计分别确认；不支持更新的端点不能误确认新快照，越权请求不改变在线或统计 |
| 关闭与恢复 | TUI 切换／退出和 Web 删除／退出提交最终状态；信号及页面提示尽力处理；强制重启恢复原实例、环境和已保存时间 |
| 更新去重 | 同一实例多次回答只计一场会话；重复、乱序、旧确认与关闭并发不覆盖新快照，不重复累计 token、工具或扣点 |
| 双端队列 | 各端独立确认，一端失败不阻塞另一端；恢复后可自动补发，重传不重复入库 |
| 上传身份 | OA 上传者来自内省；安装签名保持匿名历史，不以登录回填操作人 |
| 环境 | PE、探测失败和缺失字段保持未知，不上传原始系统标识 |
| 跨机归属 | 原机器与当前机器 PID 碰撞时，终止实例的草稿仍可恢复；活动实例不被其他进程覆盖 |
| 本地诊断 | 保存版本、各端确认、最近心跳及失败类别可核对；不记录凭据，禁用后不产生新状态 |
| 迁移与汇总 | 原始 payload 保留；未知列为 NULL，真实零值为 0；汇总与 CSV 使用相同口径 |
| 隐私与禁用 | 请求 ID 只留本地草稿；常规字段不含正文、令牌和密钥；关闭遥测后不采集、不查账、不上传 |

执行阶段见[触发与心跳改造计划](../telemetry/trigger-upgrade-plan.md#阶段与验收)，协议见[版本化提交](../telemetry/schema.md#版本化提交)。以上为验收要求，须分别记录实际结果。

## 本地验证结果

2026-10-27：发送端检查通过，遥测单元测试 45 项通过，Web API、生命周期、提示与关闭测试 18 项通过，前端测试 174 项及类型检查通过；接收端 Go 测试及 vet 通过。真实 Pi 与两个本地 Go 接收端的集成测试通过，覆盖 `0.1` 补发及 `0.2` 回答结束上传、同一活动实例连续提问累计替换、逐版本确认、签名与 OA 同传、旧版本重传、最终状态、纯心跳独立确认、关闭心跳及 CSV。

可控时钟已覆盖心跳周期、休眠间隔合并、90 秒超时及读取重判；已验证慢端合并、统计积压不阻塞、双端独立、过期拒收不丢统计、关闭终态和在线状态保留期。关闭已覆盖旧实例失败后重试、同会话多实例草稿、并行统一预算及延迟查账不改最终版本。子进程测试覆盖活跃所有者跳过、退出后 PID 碰撞恢复、复制锁回收与并发恢复封存。

页面提示已验证同源限制、keepalive、事件清理、禁用不建状态及不销毁实例；退出失败后重试重新计时。本地诊断覆盖保存、逐端入队与精确确认、心跳、失败类型、条数上限及敏感信息排除。

Windows 直接重启、真实换机和拔盘实测未执行。未修改生产服务，未重放实际 U 盘记录。

## 真实服务与环境验证

真实服务测试使用隔离 home 和独立测试版本标记，核对以下内容：

1. 一次回答结束后保持程序运行，两端均出现该实例统计；再次提问后两端更新累计值，会话数保持一场。移除服务端补充字段后，同一快照内容与本地一致。
2. 请求 ID 对应的网关账单与已确认扣点一致；部分确认时同时报告覆盖数量。
3. 断网恢复、凭据失效与重新登录后队列可补发，记录内容和原始环境保持不变。
4. 回答完成后直接重启，核对已入队快照及下次启动恢复；处理中强杀，核对最后草稿与不完整用量。首次设备授权、生产 APIKEY、多成员、介质写保护、跨机及长期网络抖动分别验证。
5. 保持长任务或空闲运行，核对心跳与变化快照；分别断开一端、休眠并恢复，核对失联与恢复状态，确认时长和会话数不因心跳增加。
6. 备份独立核对一致性、异机保存和完整恢复；健康检查确认返回接收端 JSON 及所需协议能力。

来源网段可能是反向代理地址，不能据此认定客户端地点。生产验证不修改其他记录、账户余额或服务配置；日志和临时凭据放仓库外当天临时目录。

发布与运维顺序见[遥测部署](../telemetry/deployment.md)。每次验证记录对应版本、环境、实际结果与未执行项，单次通过不代表所有目标环境通过。
