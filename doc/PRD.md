# PRD — cst-pilot 诊断工具链

辅助维修人员上门诊断：机主描述症状，pi Agent 调用只读诊断工具现场定位原因。

## 需求

| # | 需求 | 回答的问题 | 实现 |
|---|---|---|---|
| R1 | 进程盘点：内存 / CPU 占用 Top N | 哪些进程占用资源 | `sys(proc)` ✅ |
| R2 | GPU 状态：每进程利用率与显存，独显附温度功耗 | GPU 忙不忙 | `sys(gpu)` ✅ |
| R3 | 传感器：温度 / 风扇 / 电压 | 是不是过热 | `sys(sensor)` ✅ |
| R4 | 整机概况：内存 / CPU 总占用 / 页面文件 / 开机时长 | 整体负载如何 | `sys(overview)` ✅ |
| R5 | 开机自启盘点：注册表 / 启动文件夹 / 自启服务，含禁用状态 | 开机拉起了什么 | `startup` ✅ |
| R6 | 事件日志痕迹：错误警告、蓝屏与关机史、应用崩溃、服务故障、登录审计，可查询 | 过去发生过什么 | `eventlog` ✅ |
| R7 | 设备与驱动健康：异常设备、关键硬件现状、外设、指定查询 | 设备和驱动有没有问题 | `driver` ✅ |

存储分析独立成族：目录大小浏览（`ls`）、磁盘空间 / 健康 / 占用扫描（`disk`），✅ 已实现。

## 命令交付需求

✅ 已实现：`runbook`。工具文档 [runbook](tool/runbook.md)，命令写作规范见 [skills/runbook](../agent/home/skills/runbook/SKILL.md)。

诊断只读，修复动作只能由队员手动执行。模型把待执行的命令整理成 txt 文件，队员打开文件逐条复制，不必从聊天记录里翻找。

| # | 需求 |
|---|---|
| D1 | 一次调用输出一份命令清单，每条含一句话说明（功能与影响）、命令正文、执行环境（cmd / PowerShell）与是否需要管理员 |
| D2 | 清单写到工具包 `outbox\<日期>\` 下，文件名带当天唯一递增的序号与标题；沿用已有序号重写该份清单即为修正，不新增文件 |
| D3 | 一次调用只产出一个文件；命令按风险分三档（安全 / 较安全 / 需与机主确认），同一档合并成一份清单 |
| D4 | 只生成 `.txt`；新清单使用新序号，修正时仅替换指定序号的清单；不生成 `.bat` / `.cmd` / `.ps1` 等可双击执行的脚本 |
| D5 | 文件不使用 Markdown；每条命令四行：环境、说明、命令标签、命令正文；正文独占一行、不带前缀，条目之间空行分隔 |
| D6 | 每条命令一句话说明功能与影响；不可逆或可能造成数据丢失的命令必须写明 |
| D7 | 功能相似的多条操作合并为一条命令，不逐条罗列 |
| D8 | 中等及以上风险、不可逆且无退路的操作不进入任何清单 |
| D9 | 文件头一行概括（标题、风险档、生成时间），正文只含条目，不重复诊断上下文 |
| D10 | 返回文件绝对路径、序号与条目数，模型必须转述，队员据此在工具包内定位文件 |
| D11 | 写入失败（介质只读、空间不足、文件名不合法）返回结构化错误与原因，不静默失败 |
| D12 | 除 `outbox\` 下的清单 txt 外不落任何文件；不写注册表、系统配置与机主文件 |

风险分档、命令合并规则与说明措辞由 SKILL 规范，工具只保证落盘与版式。

## UI 通道

| 通道 | 入口 | 说明 |
|---|---|---|
| TUI | `pi.cmd` | 当前可用通道；启动 Web 后留作待机宿主，停止接收交互 |
| Web | 启动 pi 后执行 `/web` | 开发版提供预览页和本机回环接口；完整页面交互及发行接入待完成 |

## Web 通道需求

| # | 需求 |
|---|---|
| W1 | 高度定制；第三方库可大方引入，打包分发保持简单 |
| W2 | 设计稿走专用设计软件（Figma 类），动效专门设计 |
| W3 | 现代观感：动效精美、UI 极简；每个诊断工具一张卡片 |
| W4 | 兼容版以 2020 年内核（Chromium 86 级）为目标，**排在 MVP 之后**；React 19 与 react-router 的产物已实测通过，Tailwind 需分两版 |
| W5 | 在本项目开放的能力范围内完整替代 TUI 操作界面，包括会话管理、模型与凭据配置、扩展交互，以及 `/new`、`/resume`、`/model`、`/tree`、`/settings`、`/login`、`/compact` 等内置命令；TUI 通道保留 |
| W6 | 基于 pi 内核，在 TUI 中执行 `/web` 后由 Web 接管操作；TUI 进程和窗口保留待机，禁用输入。Web 共用会话记录、模型配置与凭据；同一会话只有一个执行实例，工具权限由后端控制 |
| W7 | 随便携发行版提供预构建产物，现场无需安装运行时或执行构建命令 |
| W8 | 遵循现代本地 Web 的导航行为，支持页面地址、刷新与前进后退；Web 内切换会话不中断任务，不同会话可以同时执行 |
| W9 | TUI 先释放已落盘的原会话，Web 再接管；页面关闭或断连不释放仍在执行的会话。Web 各端可同时打开同一会话，执行状态共享 |

页面与多会话要求见 [会话运行与并行](web/SPEC/session-runtime.md)，地址与接口见 [页面地址与接口设计](web/SPEC/app-router.md)，工程组织见 [前端工程](web/SPEC/frontend.md)。工程约束见 [Web 技术决策](web/research/tech-decisions.md)：在 pi 进程内自建 runtime 承载 Web 会话，不新增进程、不改 Pi 内核；页面为静态产物，运行期只有一个服务器；两版共用 React 19，Tailwind 分版。Web 使用机主电脑上的浏览器；系统范围保持 Windows 10/11 x64，PE 等环境单独验证。

## 约束

- 诊断只读：不主动改写机主文件、注册表或系统配置，不安装驱动；修复由队员手动执行
- 工具包内允许写入：`agent/home/` 保存凭据、配置、会话与遥测队列，`.state/` 保存运行状态，`wiztree/tmp` 保存扫描临时文件，`outbox/` 保存命令清单。操作系统自身的日志与缓存边界见 [运行边界](Notice.md#运行边界)
- 零宿主安装：只用仓库自带运行时
- 需管理员的能力必须可降级：明确提示，其余能力不受影响
- 常规查询尽量秒级返回；扫描耗时由目录规模、权限和介质决定，超时与不完整结果须明确说明
- 输出结构化，保留业务数据、说明与错误，包装约定见 [工具文档](tool/README.md#返回结构)

项目待处理事项见 [议题清单](issues.md)。
