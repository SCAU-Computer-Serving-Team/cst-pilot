## 对话流

一轮回答由这些部分组成，按模型实际输出顺序排。同一条助手消息中的正文可出现在工具调用之前或之后，不统一移到工具调用末尾。

| 部分 | 呈现 |
|---|---|
| 用户消息 | 气泡，右对齐 |
| 思考 | 一行状态「已思考 · 摘要」，可展开看完整思考。展开内容按正文样式呈现，不加背景、边框与圆角 |
| 工具调用 | 折叠成一行摘要，见下节 |
| 联网检索 | 一行状态「正在联网检索…」加检索关键词，运行时带转圈 |
| 正文 | 按 markdown 渲染，代码块做语法高亮，表格渲染成表格，链接在新标签页打开 |
| 消息末尾操作条 | 助手消息末尾一条：复制、分叉（从该回答另起分支）、导出；右端显示消息时间（如 19:35）。不做点赞与点踩。只出现在一轮回答的最后一条助手消息上，中间轮次不显示 |
| 消息菜单 | 标题栏右上角三个点弹出；MVP 含「分支树」项，跳转到[分支树视图](branch-tree.md)。分享未进入当前范围，不显示 |
| 分支总结 | 独占一块：标题行「分支已总结」加消息时间与折叠箭头，默认折叠；展开后正文收进灰底原文块，按 Markdown 原文呈现（不渲染），保留原始换行。由树页导航时选「总结」产生，见[分支总结](branch-summary.md) |

## 过程折叠

一轮回答 = 一条用户消息 + 其后全部助手消息（agent 循环里一轮可含多条助手消息）。一轮里除最后的正文以外的内容（思考、工具调用、中间正文）都是过程内容，整体收进一条可折叠的过程区；最后的正文不参与折叠。

| 部分 | 规则 |
|---|---|
| 过程行 | 运行中「工作中 N 秒」，完成后「已工作 N 秒」；下方一条 `--chat-bubble` 发丝线；文字后紧跟统一的三角指示 |
| 默认状态 | 运行中展开；完成后自动折叠（用户手动操作后不再跟随）；历史回放折叠 |
| 等待态 | 还没有任何助手内容时，过程区内显示「......」流光文字（transitions.dev shimmer text） |
| 耗时口径 | 起点取用户消息时间戳；运行中实时计；结束时冻结；历史回放取轮内最后一个时间戳，为近似值 |

## 动效

取值一律用 transitions.dev 令牌刻度，见 [DESIGN.md 动效](../../../DESIGN.md#动效)。

| 场景 | 过渡 |
|---|---|
| 发送消息 | 用户气泡从输入框方向滑入（250ms，上移 12px 淡入） |
| 流式正文与思考 | 逐词显现并淡入（transitions.dev streaming text，350ms 交叉模糊）；代码块不包裹 |
| 过程行与思考行、工具卡片出现 | 块级淡入（250ms，上移 4px） |
| 等待首个内容 | 「......」流光文字，左到右循环（2000ms） |

历史回放与减少动效（prefers-reduced-motion）下不播放上述动画。

## 流式渲染策略

流式期间每帧只重解析增量尾部：正文按安全分割点切成「已定稿前缀 + 流式尾段」，前缀 memo 缓存（含代码高亮），尾段跳过代码高亮，消息结束后整块重渲染一次性高亮。分割规则见 `app/app/markdown-split.ts`（未闭合代码块、列表/表格/引用延续不切）。

播放节奏用追赶式步进（opencode desktop 方案，`app/app/stream-player.ts`）：流式期间每 24ms 步进一批，步长随积压分档（2/4/8/最多 256 字），终点吸附词边界；后端帧间隔抖动被整流为匀速流，积压大时自动加速追赶；消息结束立即放行剩余。

长会话不能一次渲染全部消息。

滚动容器铺满主区：侧栏右侧整块区域都能滚动。内容列 1120px 在主区内居中，是滚动容器的子元素。滚动条不显示。

滚动跟随：用户往上翻时停止自动跟随，出现「回到底部」按钮。回到底部后恢复跟随。按钮盒高 32、圆角 6、内边距 0 12、图标 14 与文字相隔 4；浅色白底加中性 6 描边、深色中性 2 底加中性 7 描边，文字取中性 11，悬停提到正文色。

## 工具调用的折叠

工具调用按三层折叠，逐层向下展开。层级画布见 `src/web/design/cst-pilot-tools.pen` 的「工具调用 · 折叠层级 浅色」。

| 层级 | 内容 | 运行中 | 完成段 |
|---|---|---|---|
| 第 1 层 · 计数行 | 一行显示当前被折叠的调用数 | 正在调用多个工具… | 已完成检查 · N 次工具调用 |
| 第 2 层 · 工具行 | 每个被折叠的工具一行 | 正在调用 `disk` 工具… | 同左 |
| 第 3 层 · 卡片 | 单个工具的完整卡片 | 见[诊断卡片](diagnostic-cards.md) | 同左 |

各层文字的字号按 [DESIGN.md 的输出正文四层](../../../../DESIGN.md#工具调用卡片) 取值：计数行与回复正文同为第 1 层，工具行与卡片状态行同为第 2 层，卡片内容组为第 3 层，原文块为第 4 层。

规则：

1. 第 1 层与思考行、正文左侧对齐，默认折叠。展开区的工具行向右缩进 24px，第 2、3 层由用户逐层展开。
2. 第 3 层在结果返回后自动展开；历史回放默认折叠。
3. `sys overview` 与 `runbook` 打断折叠：单独占一行，自动展开，不进计数行。`web_search` 不进入折叠：单独占一行的联网检索行，属输出正文第 1 层（16px），展开仅显示传入关键词（12px），不弹出返回内容，例外画布见 `cst-pilot-tools.pen` 的「工具调用 · web_search · 例外」。

## 图片

未发送图片按内容 hash 保存在浏览器 IndexedDB，以 object URL 渲染。发送时将图片交给后端；后端把已接受的图片随会话或受管附件持久化，供模型、队列和历史回放使用。删除会话时按引用清理附件。

| 项 | 规则 |
|---|---|
| 草稿存储 | IndexedDB 保存字节，标签页分别维护草稿引用；启动时根据全部有效引用回收未使用图片 |
| 提交 | 选中与粘贴都支持。发送时随消息提交，后端确认已保存图片后才确认消息接受 |
| 浏览 | 缩略图排在输入框上方的独立卡片里：圆角 14、1px 弱边框、内边距 10、间距 8，卡片与输入框间隔 6，缩略图 80×64（圆角 8）。悬停或聚焦时显示右上角删除按钮（20×20 圆，与缩略图右上角叠 6）；点缩略图看大图 |
| 多图 | 只做横向排列，不做画廊与多图对比 |
| 格式 | 白名单 `png` / `jpeg` / `gif` / `webp` |
| 体积 | 单次提交的图片原始字节合计不超过 12 MiB，不限单张；读取时预算递减，超预算即停 |
| 数量 | 按合计预算控制，不另设张数上限 |
| 已接受图片 | 后端按内容 SHA-256 保存原始字节，路径位于 `agent/home/web-inbox/attachments/<会话 ID>/`；同一会话内相同内容共用文件。删除会话时清理该目录 |

画布：`src/web/design/cst-pilot-web.pen` 的「未发送图片 · 输入框」浅深两版。对话流画布待补，见 [Todo](../../Todo.md)。

## 排队与插队

后端按会话状态分类消息：空闲时首条消息直接投递；正在执行、暂停或有待处理消息时，新消息进入队列。只有实际排队项在聊天框上方展示。模型返回错误时，已送达的消息保持「已投递」，错误展示在助手回答中。

| 操作 | 说明 |
|---|---|
| 插话 | 将尚未投递的排队项改为插话，在下一个允许的模型调用边界投递；当前输出不中断 |
| 编辑 | 修改尚未投递的条目，由后端确认 |
| 删除 | 删除尚未投递的条目 |
| 排序 | 拖动调整尚未投递条目的顺序，由后端确认 |

| 情况 | 规则 |
|---|---|
| 主动停止 | 队列暂停，再提交一条才恢复 |
| 一条失败 | 卡在该条，不跳过 |
| 排队项归属 | 属于后端，不属于页面。刷新或切换页面不丢 |

队列本身的行为见[输入收件箱](session-runtime.md#输入收件箱)。

画布见 `cst-pilot-web.pen` 的「排队与插队」四帧（基础、暂停、失败、失败悬停），各浅深两版。正常排队不写状态行，排队条目本身就是提示。异常状态才在标题行写明：暂停写「排队已暂停 · 发送新消息后继续」，失败写「投递失败」并在行尾带圆形问号图标，悬停展开失败原因。问号只用危险色，文字与其他状态一致。暂停与失败时输入框右侧按键恢复为发送键。

## 中断

发送按钮在会话执行且**输入框为空**时变成停止按钮。输入框有内容时按钮仍是发送，因为这时点它是插话或排队。

`Esc` 与停止按钮是同一个动作。停止不改变模型与思考强度的选择。

## 编辑器

| 部分 | 内容 |
|---|---|
| 占位文字 | 「继续提问，或补充这台电脑的情况…」 |
| 操作栏 | 添加附件、模型、思考强度、发送或停止键。**不提供工具选择入口**，工具由模型自己决定调用 |
| 模型选择器 | 带上下文进度环。环按用量占比填充，接近上限时改用警告与危险色，不写数字 |
| 下方提示 | 发送快捷键、结果核验提示「诊断建议仅供参考，请结合设备实际情况核验。」 |

悬停或聚焦上下文进度环时显示上下文面板。DeepSeek 展示账户余额；OpenCode Go / Go Plus 展示 5 小时、每周、每月的剩余百分比。查询失败时显示原因；其他 Provider 不显示额度区。

文本编辑用浏览器原生行为，不复制 TUI 的按键。

| 键 | 行为 |
|---|---|
| `Enter` | 提交 |
| `Shift` + `Enter` | 换行 |
| 输入法组合中 | `Enter` 只用于选词，不提交 |

命令补全见[命令与功能对应](commands.md#输入框的交互)。

分支总结在这三处出现，取值见[分支总结](branch-summary.md#取值)：

| 状态 | 位置 | 呈现 |
|---|---|---|
| 待填提示词 | 输入框 | 「自定义总结提示词」标记块，与命令标记同一形态；标记在时回车走总结而不是发消息，删掉标记即放弃本次总结 |
| 生成中 | 正文尾部 | 一行状态「正在总结所选分支…」，右端一个取消按钮 |
| 完成 | 正文尾部 | 一条分支总结消息，与助手消息同宽同左缘 |

## 状态恢复

| 对象 | 恢复规则 |
|---|---|
| 草稿与未发送的图片 | 同一标签页刷新后恢复；其他标签页或浏览器不继承该页草稿，见[前端工程](frontend.md#状态归属) |
| 排队项与已提交图片 | 从后端恢复；其他标签页或浏览器可查看，页面关闭不影响已接受输入 |
| 滚动位置 | 不恢复 |
| 正在输出的正文 | 靠事件流续传补齐，见[接口约定](app-router.md#约定) |
