# 前端工程

状态：页面形态与工程边界已定，尚未实现。更新：2026-09-23。

本文定义 Web 前端要实现成什么样。地址与接口见[页面地址与接口设计](app-router.md)，会话运行见[会话运行与并行](session-runtime.md)，视觉取值见 [DESIGN.md](../../../DESIGN.md)。

## 页面形态

**静态 SPA。** 构建期生成静态文件，运行期由扩展自己的 HTTP 服务器直接发出，地址解析在浏览器里做。

| 项 | 决定 |
|---|---|
| 构建工具 | Vite |
| 语言与框架 | TypeScript + React 19 |
| 组件库 | HeroUI v3（`@heroui/react` + `@heroui/styles`） |
| 路由 | react-router 框架模式，`ssr: false` |
| 产物 | 静态文件 |
| 运行期服务器 | **一个**，就是扩展自己的。没有转发层，没有第二个服务器 |
| 页面资源 | 发行阶段随包提供预构建产物，现场不安装、不构建 |

发行包优先控制文件数量，同时记录体积与解压耗时。

## 浏览器基线

**MVP 只做现代版**：最低 Chromium 111，随包提供 Tailwind v4 产物，`/web` 直接打开。**直接用 HeroUI v3 的组件**，不自己实现。

| 档位 | Tailwind | 最低内核 | 阶段 |
|---|---|---|---|
| 现代版 | v4 | Chromium 111 | MVP |
| 兼容版 | 3.4 | Chromium 86 | 功能完善后加，见 [MVP 后续安排](../MVP.md#六后面再做) |

Tailwind v4 要求 Chromium 111。兼容版推出前，先尝试 Edge；仍不支持时不要启动 Web，继续使用 TUI。

两版共用 React 19，共用同一套地址、接口与组件代码，只有样式与构建参数不同。切换方式见[双版本](app-router.md#双版本)。

**兼容版的目标**（现在不实现）：

| 对象 | 要求 |
|---|---|
| 组件库 | 不用 HeroUI v3 的产物 CSS，自己实现组件，DOM 结构与类名对齐 v3 |
| CSS 特性 | 不写 `@layer`、`:where()`、`:is()`、`:has()`、`@container`、`color-mix()`、`lab()`、`oklch()`、`var(--x, )` 空回退 |
| JS 语法 | `build.target: 'chrome86'` 保底 |
| JS 内置 API | 构建不自动补齐，按需改写或补 polyfill |

能力对照与实测依据见[实测记录](../research/measurements.md)。

## 工程边界

| 事项 | 决定 |
|---|---|
| 包标识 | `@cst-pilot/web`，写入 Web 工程 `package.json` 的 `name` |
| 扩展目录 | `agent/home/extensions/web/`，随发行包分发 |
| 前端源码 | `src/web/frontend/`，**不进发行包** |
| 前端产物 | `agent/home/extensions/web/static/`，构建产生，不入 Git |

前端源码放在扩展目录之外，是为了让 `pack/pack.mjs` 对 `agent/home/extensions/` 的整目录复制规则不需要为 Web 开例外。

## 目录划分

```
src/web/frontend/                    前端源码，不进发行包
                                    页面外壳、路由表、组件、样式与构建配置
agent/home/extensions/web/           扩展，进发行包
├── index.ts                         入口：起服务器、注册 /web 命令
├── server/                          服务器骨架、接口处理器、与 runtime 的对接
└── static/                          页面产物，MVP 仅现代版，构建产生，不入 Git
```

源码目录内部按**功能**分层，一层一个领域：`chat/`、`cards/`、`tree/`、`dashboard/`、`settings/`、`app/`、`lib/`。不按「页面 / 组件 / 工具函数」这类技术类型分层。

## 加载与依赖边界

| 边界 | 要求 |
|---|---|
| 扩展入口 | `index.ts` 只引入服务端运行所需模块；浏览器组件和构建工具不进入扩展启动依赖链 |
| 开发配置 | Web 专用的 `package.json`、锁文件、构建脚本与 TypeScript 配置放在前端源码目录内 |
| 共享模块 | 前后端共享类型与数据转换代码。不把 Node API、凭据读取或诊断执行代码带进浏览器产物 |
| 静态服务 | 只提供 `static/` 中的构建产物，不把整个扩展工程目录当静态资源目录 |

依赖允许使用第三方库，但要控制分发文件数量，不把开发依赖树带进发行包。

## 首屏与切换

| 要求 | 约束 |
|---|---|
| 点侧栏切换会话走客户端路由，不整页重载 | 会话行本身是链接，内部只放非交互元素。链接里套按钮组件时，真实鼠标点击会走浏览器默认跳转 |
| 深色主题在首屏绘制前生效 | 服务器发 `index.html` 时按主题 cookie 把 `data-theme` 写进 `<html>`。**不在 head 里塞内联 script**，水合时节点对不上会报错。`<html>` 需要 `suppressHydrationWarning` |
| 浏览器导航可用 | 真实链接、地址可复制、可在新标签打开、支持刷新与前进后退 |

## 状态归属

| 状态 | 归属 |
|---|---|
| 会话历史、执行状态、输入队列 | **后端**。浏览器不修改 |
| 占用关系 | **后端**，进程级共享 |
| 输入草稿与未发送的图片 | 浏览器，**按标签页隔离命名空间**，两个标签页不互相覆盖 |
| 滚动位置、菜单与卡片展开 | 浏览器。纯展示状态 |

## 接口调用

| 时机 | 做法 |
|---|---|
| 页面首屏 | 先取 `/api/state` 拿启动快照，避免串行发十几个请求 |
| 每个页面的数据 | 该页面自己取 |
| 提交消息 | 提交后**立即返回**，不等模型；结果从事件流回来 |
| 流式 | 每个会话一条 SSE |
| 断线恢复 | 先取状态，再决定是否重连事件流；不自动重发已接受的输入 |

| 事件 | 页面动作 |
|---|---|
| 消息开始、增量、结束 | 追加或更新当前消息 |
| 工具调用开始、进度、结果 | 按 `toolCallId` 关联同一张卡片 |
| 执行状态变化 | 更新停止按钮与排队区 |

**刷新时要能接上正在进行的流**：页面挂载后先取当前状态，仍在执行才重连事件流。

## 打包接入

前端源码位于扩展目录外，`pack/pack.mjs` 可继续整目录复制扩展。后续需增加静态产物存在性、文件清单与许可证校验。

| 进包 | 不进包 |
|---|---|
| `index.ts` 与 `server/` 下的运行文件 | 前端源码 |
| `static/` 下的现代版产物；兼容版在后续加入 | 开发依赖、构建缓存、锁文件 |
| 必要的许可证 | 构建工具产物 |

## 用户可见的约束

使用者会把它跟普通 AI 对话工具同等看待，**不会因为「这是本地工具」而降低预期**。

| 不要出现 | 为什么 |
|---|---|
| 将端口号、IP 作为主要操作说明 | 常规操作应有明确入口；浏览器地址栏仍显示本地地址 |
| 用运行时术语代替操作说明 | 提示应说明当前状态和下一步操作 |
| 只显示 HTTP 状态码或异常栈 | 主提示应说明原因，技术详情可单独展开 |
| 长期转圈「正在连接…」 | 让人觉得工具不行 |
| 手动刷新按钮 | 正常网页不需要 |

| 要求 | 备注 |
|---|---|
| 关掉 pi 后不静默变死 | 事件流断开时挂持续横幅。端口关了浏览器会报错，只能做到「告诉用户」 |
| 长会话滚动不卡 | 长会话不能一次渲染全部 |
| 只面向桌面 | 不做窄屏与触摸适配。Web 在机主电脑的浏览器上使用 |
| 报错可理解 | 说明失败原因和可执行的下一步 |
| 粘贴图片 | 规则见[聊天工作台](chat-workspace.md#图片) |
| 界面文案 | 中文 |
| 主题 | 默认跟随系统，可在设置视图切换 |
| 不做独立帮助视图 | 快捷键表与命令列表分别在设置视图与补全面板里 |
