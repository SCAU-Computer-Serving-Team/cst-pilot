# 分支总结

状态：三种选择、接口与前端处理已实现，端到端验证通过。更新：2026-10-01。

本文定义从分支树做导航时的分支总结：三种选择的后果、状态流转、接口与前端处理。命令入口见[分支树](branch-tree.md)，画布取值见 [DESIGN.md](../../../DESIGN.md)，画布帧为「分支总结 · 确认 / 自定义提示词 / 生成中 / 完成」各浅深两版。除确认帧（带遮罩，底图为树页快照）外，另三帧都是聊天页的实时副本，可在画布上直接改。

## 前提

pi 的总结与导航在**同一次调用**里完成：`session.navigateTree(targetId, { summarize, customInstructions })` 先按「当前叶指针 → 目标条目」收集那段被抛下的分支，生成总结，再移动叶指针，把总结条目挂在新叶位置。叶指针一移动，那段分支就找不回来了。

由此决定了 Web 的做法：树页只负责记下选择，真正的请求在聊天页发起。

| 选择 | 后果 | 画布 |
|---|---|---|
| 不总结 | 直接导航。目标条目是用户消息时，它的正文回到输入框，可以改完再发 | 「确认」 |
| 总结 | 导航加总结。正文回到目标位置，尾部先出现一条待总结状态行，完成后就地换成一条分支总结消息 | 「生成中」「完成」 |
| 用自定义提示词总结 | 视图先回到目标位置，输入框出现「自定义总结提示词」标记块；输入提示词回车才发请求，此后同「总结」 | 「自定义提示词」 |

三个选项都在同一张「确认」卡片里，卡片有标题「选择」与关闭按钮。点外部、Esc、关闭按钮都只是关掉卡片，不做任何导航。

## 状态流转

1. 在树页选中一行，弹出确认卡片。
2. 选「不总结」：树页直接调 `POST /tree/navigate`，成功后跳到聊天页。
3. 选「总结」或「用自定义提示词总结」：跳转到 `/s/<id>?branch=<entryId>&mode=summarize|custom`，树页不调接口。
4. 聊天页读地址参数：`summarize` 立刻发请求；`custom` 等输入框回车。
5. 请求回来后清掉地址参数，刷新消息；被取消时提示「已取消分支总结，会话位置没有变化。」。

参数留在地址里，刷新后待办还在。参数一旦清掉，这次待办就算结束。

## 接口

| 接口 | 请求 | 响应 | 说明 |
|---|---|---|---|
| `POST /api/sessions/<id>/tree/navigate` | `{ entryId, summarize?, customInstructions? }` | `{ id, entryId, cancelled, editorText?, summaryEntryId? }` | `summarize` 为真时同步等总结生成完；被取消时返回 `cancelled: true`，HTTP 仍是 200 |
| `POST /api/sessions/<id>/tree/abort` | `{}` | `{ aborted: true }` | 只中止分支总结，不动正在跑的回合，也不暂停队列 |

`tree/abort` 不走 `writeOnce` 的会话写锁。总结进行中时导航请求一直占着写锁，排队会让取消永远迟到。中止一颗 `AbortController` 本身幂等，不需要去重。

被取消的导航不报 409：取消是用户主动发起的正常结果，报冲突会让前端把它当成错误。

## 前端处理

| 位置 | 处理 |
|---|---|
| 地址参数 | `branch=<entryId>&mode=summarize\|custom`，由 `app/branch-summary.ts` 解析与拼装 |
| 跨页待办 | 只靠地址参数，不用额外的全局状态；刷新仍有效 |
| 待总结状态行 | 请求期间在正文尾部渲染一条状态行，完成后撤掉 |
| 分支总结消息 | `entries` 里 `type` 为 `branch_summary` 的条目会转成 `role: "branchSummary"` 的消息，独占一块渲染 |
| 输入框标记块 | 与命令标记同一形态，标记在时回车走总结，不发消息 |
| 叶指针未动时的视图 | 显示旧分支。导航落地后正文才切到目标位置并带上总结 |

## 与 TUI 的差异

| 差异 | TUI | Web |
|---|---|---|
| 目标条目正文 | 用户消息的正文回填编辑器，总结与自定义提示词都如此 | 「不总结」回填；总结与自定义提示词不回填（自定义提示词这一态输入框留给提示词） |
| 自定义提示词 | 弹编辑器收指令，收完再导航 | 先回聊天页，在输入框里收指令，回车再导航 |
| 生成中 | 状态指示器在状态栏 | 正文尾部一条状态行，右端可取消 |
| 取消之后 | 重新打开选择器，保留原选中 | 停在原处，提示已取消，需要重新进树页 |

| 元素 | 取值 |
|---|---|
| 确认卡片 | 宽 424、内边距 24、圆角 16、1px 中性 6 描边、投影 0,24 blur 64 中性 12 的 20%；遮罩为中性 1 的 15%（`#060B0E26`） |

| 待总结状态行 | 高 30、与上一块相隔 24、图标 18 与文字相隔 10；图标 `git-branch` 取分支总结色，文字 16 正文色，右端取消按钮 26×26（图标 18、危险色） |
| 分支总结消息 | 标题行 28 作折叠触发器（图标 18 取分支总结色、标题 16/500 正文色、时间 13 中性 11、最右端 chevron 14 中性 11；折叠朝右、展开朝下），默认折叠；块内间距 12，展开正文收进灰底原文块（同工具调用原文块：底取 `--tool-raw`、圆角 6、内边距 10 12、正文 11px 等宽、行高 1.6），总结输出按 Markdown 原文呈现、不在聊天流里直接渲染 |
| 输入框标记块 | 高 26、圆角 6、内边距 0 8、图标 16 与文字相隔 8；底取中性 4、图标取强调色、文字 16 正文色 |

## 验证

`agent/home/extensions/web/test/branch-summary.e2e.ts`，先构建前端再跑：

```
cd src/web/frontend && npm run build
cd agent && node --test home/extensions/web/test/branch-summary.e2e.ts
```

六个场景覆盖：确认卡片三选项、总结全程、自定义提示词全程、标记块样子、标记块去掉、生成中点取消。证据写在 `E:/tmp/<日期>/branch-summary/`：`branch-summary.md` 是逐项结果，`summarize.png`、`custom.png`、`tag.png`、`drop-tag.png`、`pending.png`、`cancel.png` 是各状态截图。假模型对总结请求故意延迟，否则待总结状态行一闪而过，截不到。
