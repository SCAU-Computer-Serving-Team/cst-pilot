# 分支树

状态：行结构已按 pi TUI 规则重画并对齐实现，页面已接入接口。更新：2026-09-30。

本文定义分支树视图 `/s/<id>/tree` 的呈现与交互。规则直接对齐 pi TUI 的 `TreeList`：`agent/node_modules/@earendil-works/pi-coding-agent/dist/modes/interactive/components/tree-selector.js` 的 `flattenTree`、`recalculateVisualStructure` 与 `isFoldable`。命令承载见[命令与功能对应](commands.md)，接口见[页面地址与接口设计](app-router.md)，视觉取值见 [DESIGN.md](../../../DESIGN.md)。画布：`src/web/design/cst-pilot-web.pen` 的「分支树」浅深两版与「分支总结」四态（确认、自定义提示词、生成中、完成，各浅深两版）。

## 入口

| 入口 | 行为 |
|---|---|
| 斜杠命令 `/tree` | 补全面板选中即跳转，不留标记，不取后续输入 |
| 消息菜单 | 聊天标题栏右上角三个点 →「分支树」跳转 |
| 直接地址 | `/s/<id>/tree`，支持刷新与前进后退 |

标题栏右端的关闭按钮返回聊天工作台 `/s/<id>`。

## 数据

| 接口 | 用途 |
|---|---|
| GET `/api/sessions/<id>/tree` | 条目树与当前叶条目，对应 `sessionManager.getTree()` 与 `getLeafId()` |
| POST `/api/sessions/<id>/tree/navigate` | 导航到选中条目，对应 `session.navigateTree` |

导航语义与 TUI 一致：选中用户消息时叶指针移到其父条目、正文回到输入框；选中其他条目时叶指针移到该条目。选中一行会弹出确认卡片，三个选项的后果、接口与前端处理见[分支总结](branch-summary.md)。会话执行中时导航接口返回 409。

## 页面结构

1. 标题栏：会话标题加「· 分支树」后缀，右端关闭按钮。
2. 过滤工具栏：搜索条目、视图过滤（默认视图）、全部展开、全部折叠，右端为选中行序号与可见总数。
3. 树列表：每条目一行，滚动容器。

## 可见条目

默认视图与 TUI 一致：

- 隐藏设置类条目：label、custom、model_change、thinking_level_change、session_info。
- 隐藏无正文的 assistant 消息；错误、中止与当前叶条目除外。
- **被隐藏条目的子条目挂到最近的可见祖先**，层级与连接符都按可见树重算。所以隐藏条目会改变分叉：两个子条目藏掉一个，父条目就不再是分支点。

视图过滤的其他档位（无工具、仅用户、仅标记、全部）画布未画，待定。

## 排序

深度优先前序。每个父条目下，含当前叶的子树排最前，其余按时间戳。多根时，根按同一规则排序。

## 行布局

行高 40，缩进一列 32px，列起点 x = 36 + 32c。图标在缩进列之后 6px，角色文字紧随图标。

### 缩进与标记

「分叉」只数**可见子条目**的个数：`子条目数 > 1` 就是分支点。以下四个参数决定每一行长什么样，与 TUI 一一对应。

| 参数 | 规则 |
|---|---|
| 缩进 indent | 根为 0；父条目是分支点 → 父 +1；**段首的第一代再 +1**；其余与父相同（单子链条持平） |
| 连接符 | 只画在分支点的子条目上，不画在分支点自己身上 |
| 连接符列 | `indent − 1`，即该行缩进列的最后一列 |
| 竖线 | 段首把 `(自己的列, show = 自己不是同级末位)` 传给全部后代 |

由此得到几条必须守的性质：

1. **一列对应一个分支点，该列的方块数就是该分支点的可见子条目数**，因此每列的方块不少于 2 个。最左列同样会有方块。
2. **竖线不竖到底。** 它只存在于非末位兄弟的子树行里，到末位兄弟那一行（方块行）为止；末位兄弟的后代在这一列留空。
3. **根与根到首个分支点之间的单子链条没有任何标记**（前缀为空），缩进也是 0。
4. 多根时按虚拟根处理：根缩进 1、不画连接符，显示时整体左移一级。虚拟根也不注册竖线，所以多根的树里没有任何方块与竖线，只靠缩进表达层级。

段首指「根条目」或「父条目是分支点的条目」。段首的第一代再进一级，作用是让分支的后续链条与同级的另一条分支在视觉上分开。

| 画布元素 | 形态 | 浅色 | 深色 |
|---|---|---|---|
| 方块 | 10×10，所在列左缘，行内垂直居中 | `#0665BE` | `#77B4FF` |
| 竖线 | 2px 宽，位于方块列中心，贯穿整行 | `#D5DEE3` | `#4F575B` |

TUI 用 `├─` `└─` `│` 三个字符画这些位置；Web 用方块与竖线表达同一个结构。TUI 在活动路径的行首画 `•`，Web 改用行底色加右端的「当前位置」。TUI 在连接符列用 `─` 占位不可折叠的行，Web 的列宽固定 32px，不需要占位符。

### 行内容

| 条目 | 呈现 | 浅色 | 深色 |
|---|---|---|---|
| user | `user:` 加内容，16px | 角色 `#0665BE`，内容 `#1A2024` | 角色 `#77B4FF`，内容 `#E0EAEE` |
| assistant | `assistant:` 加内容，16px | 角色 `#007B3A` | 角色 `#67CA83` |
| 工具结果 | `[工具名]` 加结果首行摘要，13px；结果为空时回退到参数摘要 | `#5F676C` | `#AAB3B7` |
| 压缩 | `压缩 · Nk tokens`，16px | `#5F676C` | `#AAB3B7` |
| 分支总结 | `分支总结 · 摘要`，16px | `#8C5A00`（图标），文字 `#5F676C` | `#ED9F26`（图标），文字 `#AAB3B7` |

内容单行截断。行首图标按类型取 user / bot / wrench / minimize-2 / git-branch。

工具行给结果首行摘要而不是 TUI 的参数摘要，这是 Web 侧的取舍：诊断工具的参数通常只有 action 与 mode，结果首行更能说明这一步做了什么。

### 折叠

可折叠行与 TUI 的 `isFoldable` 一致：**有可见子条目，且自己是根条目或段首**。分支点自己不是段首，因此不可折叠。

| 状态 | 行尾 |
|---|---|
| 展开 | `▾`（14px） |
| 折叠 | `▸` 加「已隐藏 N 条」（12px） |

浅色 `#5F676C`、深色 `#AAB3B7`。折叠隐藏该行的全部可见后代，N 为被隐藏的可见条目数。工具栏的「全部展开」「全部折叠」清空、填满整个折叠集合。

### 当前位置

当前叶条目所在行整行加底色（浅色 `#EAEAEA`，深色 `#242C2F`），右端显示「当前位置」（12px，浅色 `#0665BE`，深色 `#77B4FF`）。工具栏右端计数为当前叶的可见行序号与可见总数（如 `17 / 20 条`）。
