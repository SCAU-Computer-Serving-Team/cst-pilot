# 会话运行与并行

状态：多会话要求已定，发行二进制的单会话接管已验证，多会话管理仍待实现。更新：2026-09-23。

本文定义会话怎么运行、两端怎么共存。地址与接口见[页面地址与接口设计](app-router.md)，前端工程见[前端工程](frontend.md)，视觉取值见 [DESIGN.md](../../../DESIGN.md)。

## 产品要求

CST Pilot 是现代本地 Web 应用。TUI 负责启动，执行 `/web` 后留在原进程中待机；会话交互由 Web 承担，两者共用隔离 home。

| 事项 | 要求 |
|---|---|
| Web 内切换会话 | 只改变当前显示的会话，不中断、暂停或销毁离开的会话 |
| Web 多会话执行 | 不同会话可以同时运行，分别维护消息、上下文、执行状态与取消信号 |
| 停止任务 | 只作用于指定会话，不影响其他会话 |
| 追加输入 | 后端先接受并持久化，再按[输入收件箱](#输入收件箱)区分插话与排队。队列中的「插话」不停止当前输出 |
| 返回会话 | 展示该会话的最新执行状态与已有结果，不重新提交上一条输入 |
| 数据事实 | 会话历史与执行状态由后端维护；浏览器只维护展示状态与未提交输入 |
| TUI 待机 | `/web` 后 TUI 不再接受消息或会话操作；窗口保留，隐藏或最小化的方式待实现 |
| 写权 | TUI 释放原会话后由 Web 接管；Web 各页面共享每场会话的执行实例，见[写权与会话串行](#写权与会话串行) |
| 会话池 | Web 使用原来的 `agent/home/sessions/`，包含此前 TUI 已保存的会话 |
| Web 操作范围 | 本项目所需的会话、模型、凭据、设置及扩展交互均可在 Web 完成，不要求切回 TUI |
| 命令覆盖 | Web 必须覆盖 TUI 的内置命令。逐条对照与否决清单见[命令与功能对应](commands.md) |

## 路由与执行分离

页面路由回答「当前查看什么」，会话运行回答「哪些任务正在执行」。页面导航只改变查看对象，不改变执行。

| 对象 | 职责 |
|---|---|
| 页面路由 | 决定显示主页、指定会话或仪表盘；管理浏览器导航 |
| 会话运行实例 | 承载一场对话的模型调用、工具执行、排队、中断与事件 |
| 会话管理模块 | 按会话 ID 查找或创建运行实例，管理生命周期 |
| 会话串行 | 同一会话只有一个执行实例，同时只跑一轮；唤醒合并、中断即打断 |
| 页面局部状态 | 输入草稿、滚动位置、菜单与卡片展开状态，不作为执行事实 |

约束：

1. 不同会话的命令、事件与展示缓存按会话 ID 隔离，不能只用一个全局「当前会话」。
2. 同一会话不能因为刷新、重复打开、多个标签页或换端而创建多个写入同一记录文件的执行实例。
3. 刷新与断线恢复只读取状态、恢复订阅，不自动重发已接受的输入。
4. 会话间独立不代表硬件资源无限。磁盘扫描、命令清单写入及供应商并发限制需统一协调，但**不能用页面导航动作取消任务**。
5. 页面地址不得包含凭据或会话文件的绝对路径；后端负责把会话 ID 映射到允许访问的记录。

## 写权与会话串行

**Web 各端之间不仲裁。** 都能对同一场会话提交输入，输入都被接受，顺序由服务端确定。同一会话只有一个执行实例，同时只跑一轮，各端看到的运行状态是同一份。

| 场景 | 行为 |
|---|---|
| 两场 Web 会话同时执行 | 分别运行，互不影响 |
| 同一会话被多个 Web 页面打开 | 允许。执行实例只有一个 |
| 两个 Web 页面同时提交 | 都接受，按服务端确定的顺序执行 |
| 任一 Web 页面请求停止 | 停这场会话当前的执行轮，与是哪一端发起的无关。空闲或已结束时是空操作 |
| 关闭一个标签页，其他仍在 | 不受影响 |
| 页面刷新或短暂断连 | 不改变执行状态，恢复后重新订阅 |
| 所有 Web 页面关闭 | 执行不因此中断。**浏览器没有可靠的关窗通知**，Web 要提供明确的退出入口 |

**TUI 先释放会话，Web 再接管。** `/web` 等待当前任务结束。原会话文件存在时，通过命令上下文把 TUI 切到独立待机会话，再由 Web SDK 打开原文件；空会话尚无文件时，Web 新建会话。有未落盘的对话内容时不切换，明确提示原因，避免丢失。Web 打开其他已保存会话时也必须确认没有第二个写入实例。TUI 的编辑器进入只读待机，输入不能触发消息、内置命令或退出；窗口被操作系统关闭仍会结束整个 Pi 进程。

TUI 内置命令在编辑器中先于扩展 `input` 事件处理。只拦 `input` 或只拦会话切换事件不能实现待机。待机界面及快捷键覆盖仍需完整验证，见 [待处理议题](../../issues.md#1-承载与运行)。

页面订阅与运行实例占用分别管理。离开页面只取消本页订阅；仍在执行或有待处理输入的实例继续占用。释放前须确认实例已停止写入并完成销毁。页面关闭通知不能作为释放依据。

## 会话可见性

Web 从 `agent/home/sessions/` 发现此前 TUI 保存的会话。原会话接管后，消息与工具事件由 Web 的 SDK 实例提供；浏览器之间共享执行状态。TUI 留在独立待机会话，不继续订阅或修改 Web 正在运行的会话。

## 共享状态

TUI 与 Web 的所有会话实例共用 `agent/home`。Web 运行层按会话 ID 管理多个实例，具体 SDK 装配见[运行承载](../research/pi-capability.md#运行承载)。

| 资源 | 影响 | 处理 |
|---|---|---|
| `settings.json` | 不丢数据。写入在文件锁内重读当前文件，只写本实例改过的字段，嵌套字段按 key 合并 | 无需处理 |
| settings 读取 | 一个实例看不到另一个实例的改动 | 需要时调 `reload()` |
| `auth.json` | 安全。`AuthStorage` 按文件 revision 懒加载 | 无需处理 |
| `sessions/` | 同一文件有两个写入实例会冲突 | TUI 切换并销毁旧实例后，Web 才打开原文件 |
| `outbox/` | runbook 序号靠扩展内部的模块级串行队列分配；Web runtime 再加载一次诊断扩展会形成第二个队列，序号可能撞 | 序号分配改成进程级共享，或由单一 runtime 生成 |
| 遥测 | 每个会话实例分别累计 | 按实例记录采集周期；共享待发文件的并发读写需统一协调 |
| 长驻资源 | TUI 换会话会重建扩展实例，工厂闭包里的东西全部作废 | HTTP 服务器、Web runtime、占用表与输入队列挂进程级容器，不挂扩展实例 |
| 共享状态容器 | TUI 会话替换会重新创建扩展实例；Web 会话不再加载 Web 扩展自身 | 占用表与跨实例协调状态放进程级共享 |

## 消息与工具事件

Web 后端执行会话，前端消费结构化状态与事件。两端共用持久化记录、模型配置与凭据，不要求实时镜像。

| 数据或操作 | 规则 |
|---|---|
| 消息提交 | 按会话 ID 提交到后端，由后端确认接受并确定顺序 |
| 模型输出 | 订阅会话的消息开始、流式增量与结束事件 |
| 工具调用 | 通过 `toolCallId` 关联开始、进度、最终结果与错误；只在后端执行一次 |
| 中断 | 明确指定会话；只取消该会话的运行实例，不影响其他会话 |
| 展示形式 | TUI 用终端文本，Web 用卡片；恢复的业务数据含义一致，不要求排版一致 |
| 多标签页与重连 | 后端统一接受、排序与去重；队列按会话管理，不能只存在页面内存里，刷新或切换页面不丢已接受的排队项 |
| 输入草稿 | 属于客户端展示状态；未发送图片在浏览器 IndexedDB，已接受图片由后端持久化 |

### 输入收件箱

输入分两步落地：**先持久化收下并分配序号**，此时已经可查询、可确认顺序、重复提交只生效一次；之后在安全边界交给模型。

| 提交方式 | 交给模型的时机 |
|---|---|
| 插话 | 在下一个允许插话的模型调用边界投递，不中断当前输出；排队项可在投递前改为插话 |
| 排队 | 每个执行轮最多交一条，且只在会话本就空闲时 |

由项目后端自己实现，每个会话独立管理。前端展示后端确认的状态，不以本地乐观更新作为已接受依据。

1. 接受与投递分别持久化。重复提交和并发投递需去重；进程崩溃时无法确认完成的输入保留状态，重启后不自动重试模型调用。
2. 同一消息 ID 重复提交，只有会话、内容、提交方式三者一致时才算重试，否则返回冲突。
3. 排队项默认按接受顺序执行，拖拽排序后按后端确认的新顺序执行；每条在当前任务结束后触发一次新的用户请求。转为插话的条目只投递一次，并从排队序列移出。
4. 不同会话分别调度，不因 A 的队列而阻塞 B。
5. 队列只由一个调度主体投递。不得把同一消息同时放进项目队列与 Pi 底层队列，造成重复执行或失去控制。
6. 停止执行时队列暂停，再提交一条才恢复；一条发送失败则卡在该条，不跳过。
7. 后端重启后不再消费队列；重新进入不自动重发未完成请求。已接受的图片须与对应消息、排队项一起恢复。
8. Pi 新建会话通常直到首条 assistant 消息完成才生成 JSONL。未落盘的 TUI 空会话不作为可接管的历史会话；Web 在首次响应前按运行实例 ID 管理新会话，并将已确认接受的输入单独持久化。重启后从收件箱恢复该 ID 与待处理状态，不自动重放未能确认结果的模型调用。

## 能力范围

Web 承载本项目实际使用的操作，不把 Pi 的全部功能或终端界面直接复制进网页。**已有工具权限不因增加 Web 入口而扩大。**

| 类别 | 需要覆盖的内容 |
|---|---|
| 聊天 | 消息、流式输出、思考展示、工具卡片、中断与追加输入 |
| 会话 | 新建、列表、恢复、多会话后台执行 |
| 模型与登录 | 模型、思考强度、登录状态与退出；MVP 使用后台管理员账号的 API KEY，后续接入 OAuth。两种凭据在 Web 中都能建立模型服务登录态 |
| 设置 | 本项目需要的模型配置、外观及运行偏好 |
| 用量 | cstoa 额度及模型调用记录、用量与费用页面在 MVP 后实现，见[仪表盘](dashboard.md) |
| 扩展交互 | 选择、确认、输入、多行编辑四种用标准组件。**`ctx.ui.custom()` 不支持**，它返回的是终端渲染组件，Web 无法承载 |

首批不做：编辑重发、重新生成。输入附件只做文本与图片，PDF、Word 等文档解析不在本版。
