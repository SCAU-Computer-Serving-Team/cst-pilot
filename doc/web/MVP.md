# MVP 要做的内容

状态：待实现。产品待决事项见[待决议题](../issues.md)，待补画布见 [Todo](../Todo.md#todraw-画布)。更新：2026-09-23。

[PRD](../PRD.md) 的 W1–W9 定义 Web 的总体目标。本文划定首版交付范围，兼容版与仪表盘列在后续阶段；具体行为引用各规格。

**MVP 只做现代版**：Chromium 111 起，Tailwind v4，使用 HeroUI v3。首版使用后台管理员账号的 API KEY；后续接入 OAuth。两种凭据在 Web 中对应同一种模型服务登录态，有效期按各自机制处理。功能验证后再接入发行包。

## 一、承载

| # | 要做的 | 依据 |
|---|---|---|
| 1 | 扩展 `agent/home/extensions/web/`：起 HTTP 服务器、注册 `/web` 命令 | [前端工程](SPEC/frontend.md#工程边界) |
| 2 | 进程级容器：HTTP 服务器、Web runtime、占用表、输入队列 | [共享状态](SPEC/session-runtime.md#共享状态) |
| 3 | 扩展创建 Web 会话管理层，按会话 ID 承载多个独立实例；最小 SDK 装配已验证，多会话生命周期仍待实现 | [会话运行与并行](SPEC/session-runtime.md) |
| 4 | `/web` 启动后让 TUI 进入待机并禁用输入；Web 接管已落盘的原会话，空会话则新建；每场会话只有一个执行实例 | [写权与会话串行](SPEC/session-runtime.md#写权与会话串行) |
| 5 | 输入收件箱：先落盘分配序号，再按提交方式交给模型；停止时队列暂停 | [输入收件箱](SPEC/session-runtime.md#输入收件箱) |
| 6 | 静态产物服务：`/api/*` 走接口，其余查文件，导航请求兜底 | [路由组织](SPEC/app-router.md#路由组织) |

## 七、不做的

| 项 | 原因 |
|---|---|
| `/share` | 超出本机回环范围，四项未定 |
| 会话内搜索、会话列表搜索 | 排在后面 |
| 浏览器通知 | 本地服务，人在机器前 |
| 窄屏与触摸适配 | 只面向桌面 |
| 编辑器里的工具选择入口 | 工具由模型自己调用，不给用户开关 |
| 提示词模板、`/reload`、`/trust`、`/import`、`/hotkeys`、`/debug`、`/changelog`、`/quit`、`!cmd` | 见[命令与功能对应](SPEC/commands.md) |

## 验收

| 项 | 标准 |
|---|---|
| 替代 TUI | 在开放能力范围内，会话管理、模型与凭据配置、扩展交互都能在 Web 完成 |
| 会话接管 | `/web` 后 TUI 留在 Pi 进程内待机，Web 接管已落盘的原会话；TUI 输入不能修改会话或退出程序 |
| 登录态 | API KEY 可用于模型调用；状态与退出操作可在 Web 完成，失效时明确提示重新登录 |
| 现代版 | 在 Chromium 111 起的浏览器上跑完整个交互 |
| 本地运行 | 开发环境可用预构建页面产物运行；现场零安装在发行接入阶段验收 |
