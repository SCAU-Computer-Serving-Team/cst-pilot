# Web 发行装配可行性

官方 Pi 可执行文件、预构建 Web 和白名单扩展装配可承载当前功能。现场无需 Node、Python 或 npm，前端开发依赖不进入发行包。装配命令见 [pack](../../../pack/README.md)，当前方案见[便携发行设计](../../design/release.md)。

## 运行依据

| 部分 | 依据与边界 |
|---|---|
| Pi | 固定官方0.85.1和hash；实际进程为Bun1.3.14 / Node兼容24.3.0 |
| Web | 浏览器运行JS/CSS/字体，Pi进程提供本机HTTP/SSE；真实read与续答已通过 |
| 项目扩展 | TS由官方程序加载，运行协调与Web复用共享SDK；不另带后端运行进程 |
| 第三方JS | 固定esbuild预打包，Pi包保持external，避免重复SDK实例 |
| 原生资源 | FFF、PowerShell、WizTree、LHM按Windows x64保留必要文件与许可 |

官方的Node兼容接口属于内置运行时，前端构建用Node仅需留在构建机。原生DLL、字体和外部诊断程序各有资源路径与许可要求。

## 校验与现场范围

装配从当前前端源码重建，检查静态引用、字体、运行协调模块、许可、凭据与运行态。官方exe冒烟在独立副本执行启动、模型注册、真实read续答与退出；干净发行树不运行，ZIP按清单生成并解压复核。

完整packages下的TUI接管、待机、写权、cwd、范围与独立主题由[跨端联调](../../test/shared-backend-report.md)覆盖。该结论限定于本机隔离环境；Windows10、最低浏览器、真实U盘/跨机、普通权限、杀毒软件、生产授权与全部系统交互仍需按[Checkpoint5](../../test/checkpoint5-report.md)验证。

现场验证范围见[发行前检查](../../design/release.md#发布前检查)。版本号不代表全部目标环境已验证。
