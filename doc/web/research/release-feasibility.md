# Web 发行装配可行性

2026-10-07。**现有架构可以承载Web，无需为了加入Web而完全重写打包脚本。** 当前发行脚本已经排除前端开发依赖，使用官方Pi可执行文件承载SDK与运行时；Web仅增加预构建静态产物和后端扩展。

实验结论支持保留现有架构。当前已按[便携发行方案](../../design/release.md)补充静态资源重建、字体校验和Web实际工具链路冒烟，准备prev0.5试用包；未验证的现场范围见[Checkpoint5报告](../../test/checkpoint5-report.md)。

## 目标与边界

打包目标是减少`node_modules`中的大量小文件，保持零安装、离线资源齐备和工具权限一致。开发依赖可以保留在仓库，发行目录不复制它们。

实际官方0.85.1进程报告`Bun 1.3.14`和`process.versions.node=24.3.0`。这是官方可执行文件的内置运行时与Node兼容接口；不能把它当作额外随包分发的独立Node安装。调用HTTP、文件与进程API不要求把前端开发用Node运行时再装进发行目录。

前端使用浏览器运行的静态JS/CSS/字体，后端在Pi进程中服务这些资源。Native插件、PowerShell、WizTree等外部组件仍有各自资源和许可要求，不能仅凭文件数量全部内联。

## 实验B：实际官方程序启动Web

隔离副本通过项目启动器执行TUI`/web`。PATH按启动器白名单设置，副本没有额外的`node/`开发运行时；官方可执行文件运行于`.runtime/prx.bin`。

已验证：

1. 空会话启动服务，模型可用，浏览器打开实际页面。
2. 模拟模型提出read调用，Pi读取隔离文件并续答；发行配置保留14个开放工具。
3. 两个会话并发、停止隔离、队列暂停与恢复、刷新保留运行态。
4. 六页面浅深非headless窗口与中文组合输入辅助。
5. 原始脚本的启动、注册与模拟模型冒烟，以及资源/许可证/清单检查。

这证明当前运行时装配可以承载Web。真实生产授权、物理介质、杀毒软件、最低浏览器与跨机运行仍未验证。

## 方案判定

| 方案 | 判定 | 说明 |
|---|---|---|
| 保留官方exe＋当前装配 | 推荐作为当前基线 | 文件数量受控，实际Web链路已跑通，继续补发行验收 |
| 增加Web后端单文件步骤 | 可选增量 | 实验可行，但仅减少14个文件；需版本/许可证/SDK同实例/静态路径回归后再决定是否落地 |
| 发行完整Web开发node_modules | 不采用 | 会增加39554个文件；浏览器静态产物不需要这些开发依赖 |
| 另带Node并重打整个Pi | 暂无必要 | 会扩大SDK同实例、运行时、升级、原生模块与许可验收面；目前没有阻塞现有装配的证据 |
| 所有资源放入exe或归档运行 | 不作为本轮推荐 | 静态字体、原生DLL与外部工具的资源路径、缓存和读取方式须另行实验；缺少收益证据 |

## 发行前任务

1. 明确版本、前端构建前置校验与SDK兼容性；避免从旧静态产物或旧依赖缓存打包。
2. 发行脚本已补静态页面、模型清单、真实read续答与退出的官方exe冒烟；实际`/web`、待机与并发队列仍通过独立TUI/浏览器副本联调。
3. 保持凭据/运行态白名单、第三方许可、字体与哈希校验，检查Web资源清单能发现缺失或陈旧产物。
4. TUI待机、断线、失效提示和退出已修复并完成本机隔离回归；继续补Checkpoint5中的未验证现场范围。
5. 在移动介质、只读/写失败、无宿主Node、普通权限、杀毒软件与最低浏览器上执行发行副本测试。
6. 如采用Web后端单文件，只增加增量装配步骤，不在缺少必要性证据时替换整个运行架构。
