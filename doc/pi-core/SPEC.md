# Pi 通用核心规格

`pi-core` 模块由 `crates/pi-ai`、`crates/pi-agent`、`crates/pi-session` 与 `crates/pi-runtime` 四个独立包组成。核心对齐上游 `earendil-works/pi`（`1.6.0`），提供可嵌入任意应用的通用大模型流式调用、工具编排循环、会话树管理与运行时服务。内部架构见 [ARCHITECTURE.md](ARCHITECTURE.md)，公开编程接口见 [API.md](API.md)。

## 解耦与模块边界

通用核心与 CSTOA 认证、Windows 现场诊断及具体前端界面完全解耦。上层业务仅通过核心公开的静态扩展接口、数据策略接口与 SDK 接入自定义能力。

| 子包 | 职责范围 |
|---|---|
| `pi-ai` | 对接流式对话协议与分类器协议，内置 38 个常用模型服务商目录，管理凭据解析、OAuth 续期与 Token 计费 |
| `pi-agent` | 执行工具参数三阶段转换与 JSON Schema 预编译校验，驱动双层自动执行循环，调度串并行工具与插话／排队输入 |
| `pi-session` | 管理 JSONL v3 会话追加树、双视图上下文投影、自动／手动压缩、分支总结、静态扩展注册与崩溃恢复状态表 |
| `pi-runtime` | 提供设置与凭据存储、技能模板加载与 8 个内置编码工具。同步集成工具检索、MCP 客户端、QuickJS 代码沙箱、多模态图片归一化及无头运行入口 |

## 模型与协议规则

1. **支持协议**：固定支持 `openai-responses`（含 `openai-codex-responses`）、`openai-completions`、`anthropic-messages`、`google-generative-ai` 流式对话协议及 `typesafe-system-one` 分类器协议。DeepSeek 默认使用官方 `openai-completions` 协议。
2. **服务商范围**：内置中国大陆常用国产厂商、国际主流基座及常用聚合网关共 38 个 Provider ID，支持在运行期注册自定义服务商与模型覆盖配置。
3. **跨模型清洗**：切换模型或重放历史时自动转换思考块签名，并为未闭合的工具调用补齐错误结果，保证请求上下文合法。
4. **凭据与目录保护**：OAuth 令牌在到期前 5 分钟自动续期。网络续期失败时保留已存储凭据，不清空用户登录态。动态目录刷新支持取消与发布代次校验，防止过期响应覆盖新目录。

## Agent 循环与工具调度规则

1. **三阶段参数修复与校验**：工具执行前在深拷贝副本上依次剔除可选空值、按 Schema 宽松转换标量或单元素数组、执行预编译校验器。失败时输出点分路径错误供模型自修复，不污染历史消息中的原始参数。
2. **截断拒执行保护**：模型响应因达到最大输出长度截断时，拒绝执行当轮全部工具调用并标记截断错误。
3. **串并行与保序落盘**：默认并行执行同批工具，任一工具声明串行模式时整批转为串行。并行模式下完成事件按实际结束顺序发出，最终工具结果严格按调用顺序写入上下文。
4. **双队列调度**：执行期间的插话（`steer`）在下一个模型请求边界优先注入。普通追加输入（`follow_up`）在当前内层工具循环自然停止后消费。模型报错或用户主动取消时保留未消费队列。

## 会话、压缩与崩溃恢复规则

1. **惰性落盘与尾部修复**：新建会话在产生首条用户或助手消息前不创建磁盘 `.jsonl` 文件。普通条目单行追加并同步磁盘。加载时遇到末行未闭合 JSON 自动截断修复，头部或最后非空行存在其他损坏时保留原文件并报错，中间损坏行独立跳过且不与后续行拼接。
2. **双视图隔离**：面向模型的投影仅取活跃分支最新压缩点之后的有效对话，并按分支编辑记录隐去失败重试消息。面向界面的历史与五档过滤分支树完整保留压缩前记录、标记与自定义元数据。
3. **上下文压缩与溢出恢复**：上下文跨过保留阈值时自动压缩，且切点绝不落在 `toolResult` 上。遇到上下文溢出错误时隐去失败半轮，最多自动执行一次压缩并续跑。短会话手动压缩支持自适应折半缩减保留预算。
4. **输入去重与强杀核对**：输入与在途工具状态独立持久化。重复提交相同消息标识直接返回已有回执。进程崩溃重启后将未闭合运行标为异常中断，将未确认投递标为待核对，对禁止自动重放的受控工具生成状态核对报告，不自动重放命令。
5. **会话数据准入与脱敏策略**：允许宿主在输入预检、消息落盘与事件广播三个边界执行准入拦截或脱敏投影。投影失败或异常时立即中止写入与运行。

## 运行时与内置扩展规则

1. **信任边界**：项目未获信任时自动剥离工作目录 `.pi/settings.json` 中的自定义 Shell、命令前缀与资源扩展路径，同时屏蔽配置中的 `!command` 动态求值。
2. **内置工具与编排**：内置 `read`、`write`、`edit`、`bash`、`powershell`、`ls`、`find`、`grep` 八个基础工具（上层业务可按白名单裁剪或同名替换），并提供 BM25 `tool_search`、支持 Stdio 与 Streamable HTTP 的 `mcp` 扩展，以及基于 QuickJS（256 MiB 内存上限、超时取消与可选步数中断预算）的 `codemode` 编排沙箱。
3. **图片归一化**：`read`、`@file` 与工具返回图片统一经过 EXIF 方向修正、非标格式转 PNG 及 `2000×2000` / `4.5 MiB` 四步自适应缩放。

## 验收条件

- 四种对话协议全部通过多工具续答、思考签名保留与图片输入测试，缓存用量提取与中途取消行为符合预期。
- 会话单写权互斥、部分写入回滚与边界草案原子替换均可确定性复现。`v1 -> v3` 迁移、五档分支树几何对齐与单次溢出恢复全部通过回归。
- 独立示例程序仅调用 `pi-session` 与 `pi-runtime` 公开接口即可完成自定义服务商、嵌套工具调用、分支跳转、高危确认弹窗与无头 RPC 交互。
