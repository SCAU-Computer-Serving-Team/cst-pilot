# 阶段 1：模型核心（pi-ai）设计

本文定义独立 Rust 模型调用与目录管理包 `crates/pi-ai` 的架构设计，所属总体路线见 [0.PLAN.md](0.PLAN.md)，技术栈选型见 [prototype.md](../prototype.md)。

`crates/pi-ai` 对齐上游 `@earendil-works/pi-ai`（`1.5.0`），围绕**安全性、简洁性、高效性**实现四大流式对话协议、`typesafe-system-one` 分类器协议、26 个常用内置服务商目录及凭据续期管理。

## 设计原则与取舍

| 原则 | 在 `pi-ai` 中的落地方式 |
|---|---|
| **安全性** | 1. 用强类型枚举表示消息角色、内容块、流事件与错误码，编译期阻断非法字段组合。<br>2. 凭据存储（`CredentialStore`）与模型目录缓存物理隔离，API Key 和 OAuth 令牌禁止进入普通日志或错误消息。<br>3. 跨模型切换时执行消息清洗（`transform_messages`），自动补齐未闭合的工具调用结果。 |
| **简洁性** | 1. 直接构建 `Models` 实例与 `Provider` 工厂模式，移除旧版全局注册表兼容层。<br>2. 聚焦对话模型与 `ClassifierModel`，剔除生图模型及 16 个非中国大陆常用的海外专有云与二线算力厂商。<br>3. 协议层直接使用 `reqwest` 与轻量 SSE 解析实现，不引入多家重型官方 SDK。 |
| **高效性** | 1. 编译期直接静态链接全部协议与服务商，消除运行时动态加载包装。<br>2. SSE 字节流单次增量解析直接产出 `AssistantMessageEvent`，减少中间对象分配。 |

## 核心模块设计

### 1. 消息、内容块与流事件（`types.rs`）

数据结构与上游 JSON 序列化格式保持一致，便于直接读写会话历史。

| 类型 | 结构说明 |
|---|---|
| `Api` / `ClassifierApi` | 字符串类型别名。`known_api` 提供 `openai-responses`（含 `openai-codex-responses` 路由）、`openai-completions`、`anthropic-messages`、`google-generative-ai` 四个常量。`known_classifier_api` 提供 `typesafe-system-one` |
| `Message` | 按 `role` 区分四类：`System(SystemMessage)`、`User(UserMessage)`、`Assistant(AssistantMessage)`、`ToolResult(ToolResultMessage)` |
| `UserContentBlock` / `ContentBlock` | 用户内容块为 `Text(TextContent)` 与 `Image(ImageContent)`。助手内容块为 `Text(TextContent)`、`Thinking(ThinkingContent)`（含 `redacted`）与 `ToolCall(ToolCall)`（含 `thought_signature`、`namespace`、`arguments_error`） |
| `Usage` | 记录 `input`、`output`、`cache_read`、`cache_write`、`cache_write_1h`、`reasoning`、`total_tokens` 及按百万 Token 费率折算的 `cost` 明细 |
| `StopReason` | 共 7 个变体：`Pending`（初值）、`Stop`、`Length`、`ToolUse`、`Error`、`Aborted`、`Deferred` |
| `AssistantMessageEvent` | 流式生命周期事件：`Start` → `TextStart / TextDelta / TextEnd`、`ThinkingStart / ThinkingDelta / ThinkingEnd`、`ToolCallStart / ToolCallDelta / ToolCallEnd` → `Done` 或 `Error` |

### 2. DeepSeek 官方 Responses 协议支持

DeepSeek 官方端点原生支持 OpenAI Responses 协议，`providers/deepseek.rs` 默认启用该协议。

1. **流式思考与加密签名**：流式响应直接下发 `response.output_item.added (type: "reasoning")`、`response.reasoning_text.delta` 与 `response.output_item.done`，携带 `encrypted_content` 思考签名写入 `thinking_signature`。
2. **工具调用与细粒度用量**：原生支持 `function` 工具流式参数推送、多轮续答，并在 `response.completed` 中返回 `cached_tokens` 与 `reasoning_tokens`。
3. **兼容与调用 ID 处理**：`deepseek-flash` 与 `deepseek-v4-pro` 默认 `api` 设为 `openai-responses`，同时保留 `openai-completions` 兼容映射。`OPENAI_TOOL_CALL_PROVIDERS` 包含 `"deepseek"`，回传历史 `function_call` 条目时保留原始 UUID，不强行拼接 `fc_` 前缀。

### 3. 协议（API）与服务商（Provider）两层分离

1. **协议层（`api/`）**：接收归一化后的转录本上下文（`TranscriptContext`）、模型配置与请求选项（含 API Key、自定义请求头、观测回调、超时与 `CancellationToken`），组装 HTTP 请求并将 SSE 解析为 `AssistantMessageEvent` 流。
2. **兼容配置开关（`ProviderCompat`）**：通过 `OpenAICompletionsCompat`、`OpenAIResponsesCompat`、`AnthropicMessagesCompat` 与 `SystemOneCompat` 类型别名声明各家国产与聚合接口的字段差异（如 `developer` 角色、`stream_options`、思考字段名与严格 Schema 模式）。
3. **服务商层（`providers/`）**：通过 `create_provider` 声明 `id`、默认 `base_url`、认证方式、静态模型列表与协议映射。上层业务调用 `create_provider` 与 `models.set_provider()` 即可动态注入 `cstoa` 或用户自定义服务，无需改动 `pi-ai` 源码。
4. **观测回调异常隔离**：`on_headers`、`on_payload`、`on_response`、`on_provider_stream_event` 发生 panic 时，由 `catch_unwind` 捕获并转为带回调名称的错误，以 `AssistantMessageEvent::Error` 闭合事件流。

### 4. 凭据管理与模型目录刷新（`auth.rs`、`models.rs`）

1. **凭据解析优先级**：单次请求显式传入的 `api_key` > `CredentialStore` 已保存凭据（API Key 或 OAuth 令牌） > 服务商对应环境变量。
2. **OAuth 自动续期**：存储的 OAuth 凭据即将过期时，`Models::get_auth` 自动调用该服务商注册的 `refresh_token` 回调并写回存储。网络续期失败时保留原凭据并返回 `ModelsErrorCode::OAuth`，避免网络抖动清空登录态。
3. **代次安全目录刷新（`Models::refresh`）**：静态服务商直接返回内置目录。动态服务商先恢复本地 `ModelsStore` 缓存，在 `allow_network: true` 时并发拉取最新列表并通过发布锁与代次号原子更新缓存。新刷新或服务商变更自动取消旧刷新的等待，已开始的 OAuth 令牌轮换继续完成持久化。
