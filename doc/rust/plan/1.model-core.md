本文是 [Rust 重写开发计划](0.PLAN.md) 第一阶段「1. 模型核心」的具体设计，技术栈选型依据见 [prototype.md](../prototype.md)。

## 设计原则与取舍

| 原则 | 在 `pi-ai` 中的具体落地方式 |
|---|---|
| **安全性** | 1. 使用 Rust 强类型枚举表示消息角色、内容块、流事件与错误码，编译期杜绝非法字段组合。<br>2. 凭据存储（`CredentialStore`）与模型目录缓存隔离，API Key 和 OAuth 令牌禁止写入普通日志或错误信息。<br>3. 跨模型切换时强制执行消息清洗（`transform_messages`），自动补齐未闭合的工具调用结果，防止请求因上下文残缺报错。 |
| **简洁性** | 1. 直接采用上游 `1.5.0` 的 `Models` 实例与 `Provider` 工厂模式，彻底砍掉旧版全局注册表兼容层（`compat.ts`）。<br>2. 聚焦对话模型（Chat Model）与 TypeSafe System One 分类器（`ClassifierModel`），剔除生图模型（`ImageModel`）及 16 个不常用的海外专有云与二线算力厂商。<br>3. 协议层直接使用 `reqwest` + 轻量 SSE 解析实现，省去多家官方重型 SDK 与 `Rig` 中间层封装。 |
| **高效性** | 1. 取消上游为 Node.js 启动提速而拆分的 `.lazy.ts` 动态导入包装，Rust 编译期直接静态链接，零运行时加载开销。<br>2. SSE 字节流采用单次增量解析，直接产出 `AssistantMessageEvent`，减少中间对象分配与拷贝。 |

## 核心模块设计

### 1. 消息、内容块与流事件（`types.rs`）

数据结构与上游 `types.ts` 的 JSON 序列化格式保持一致，便于直接读写会话历史：

| 类型 | 结构说明 |
|---|---|
| `Api` | 对话协议固定为 4 种：`OpenAiResponses`、`OpenAiCompletions`、`AnthropicMessages`、`GoogleGenerativeAi`；分类器协议保留 `TypeSafeSystemOne` |
| `Message` | 按 `role` 区分三类：`User(UserMessage)`、`Assistant(AssistantMessage)`、`ToolResult(ToolResultMessage)` |
| `ContentBlock` | `Text { text, text_signature }`、`Image { data, mime_type }`、`Thinking { thinking, thinking_signature }`、`ToolCall { id, name, arguments }` |
| `Usage` | 记录 `input`、`output`、`cache_read`、`cache_write`、`reasoning`、`total_tokens` 及按百万 Token 费率折算的 `cost` 明细 |
| `StopReason` | `Stop`（正常结束）、`Length`（达到最大长度）、`ToolUse`（请求调用工具）、`Aborted`（用户取消）、`Error`（请求出错） |
| `AssistantMessageEvent` | 流式生命周期事件：`Start` $\rightarrow$ `TextStart / TextDelta / TextEnd`、`ThinkingStart / ThinkingDelta / ThinkingEnd`、`ToolCallStart / ToolCallDelta / ToolCallEnd` $\rightarrow$ `Done` 或 `Error` |

### 2. DeepSeek 官方 Responses 协议支持（已实测验证）

上游 `1.5.0` 的 `deepseek.ts` 仍使用旧的 `openai-completions`。经对 DeepSeek 官方端点（`https://api.deepseek.com/v1/responses` 与 `https://api.deepseek.com/responses`）实测验证，DeepSeek 已原生支持 OpenAI Responses 协议，表现如下：

1. **流式思考与加密签名**：开启流式请求后，官方直接下发 `response.output_item.added (type: "reasoning")`、`response.reasoning_text.delta` 与 `response.output_item.done`，并携带 `encrypted_content` 思考签名，与 `openai-responses` 的 `thinkingSignature` 机制天然吻合。
2. **工具调用与多轮续答**：支持标准 `function` 工具定义、`response.function_call_arguments.delta` 流式参数推送，以及携带 `reasoning` + `function_call` + `function_call_output` 进行多轮工具结果续答。
3. **细粒度用量统计**：`response.completed` 的 `usage` 原生返回 `input_tokens_details.cached_tokens` 与 `output_tokens_details.reasoning_tokens`。
4. **实现细节**：
   - `providers/deepseek.rs` 将 `deepseek-flash` 与 `deepseek-v4-pro` 的默认 `api` 设为 `openai-responses`，同时在 `Provider` 的 `api` 映射中保留 `openai-completions`，兼顾直接调用与旧配置兼容。
   - 在 `openai_responses.rs` 的 `OPENAI_TOOL_CALL_PROVIDERS` 集合中加入 `"deepseek"`，保留工具调用的 `call_id|item_id` 对齐。
   - DeepSeek Responses 返回的 `function_call.id` 为 UUID 格式（不以 `fc_` 开头），回传历史 `function_call` 条目时保留同源 UUID 或按上游规则省略非 `fc_` 前缀的 `id`（实测 DeepSeek 两种写法均返回 200），禁止强行拼接 `fc_` 前缀。

### 3. 协议（API）与服务商（Provider）两层分离

延续上游的核心解耦方式，将“怎么发网络请求”与“哪家服务商”拆开：

1. **协议层（`api/`）**：每个对话协议模块只接收归一化后的上下文（`TranscriptContext`）、模型配置与请求选项（含 API Key、自定义请求头、超时与 `CancellationToken`），负责组装 HTTP 请求并将 SSE 数据块解析为 `AssistantMessageEvent` 流。`typesafe_system_one.rs` 提供单次 JSON POST 结构化分类请求。
2. **OpenAI 兼容开关（`OpenAICompat` / `OpenAIResponsesCompat`）**：内置兼容配置结构体，控制各家国产与第三方接口的细微差异（如 `developer` 角色支持、`stream_options`、思考字段名 `reasoning_content` / `reasoning`、严格 Schema 模式等）。
3. **服务商层（`providers/`）**：通过统一的 `create_provider` 构造器生成 `Provider` 实例。每个内置服务商只需声明自身的 `id`、默认 `base_url`、认证方式（API Key 环境变量名或 OAuth 流程）、静态模型列表及所用的协议映射。
4. **自定义服务商与 CSTOA 扩展**：外部应用（如阶段 6 的 CST Pilot）直接调用 `create_provider` 和 `models.set_provider()` 即可注入 `cstoa` 或用户在 `models.json` 中配置的自定义服务，无需改动 `pi-ai` 源码。

### 4. 凭据管理与模型目录刷新（`auth.rs`、`models.rs`）

1. **凭据解析优先级**：单次请求显式传入的 `api_key` > `CredentialStore` 中保存的凭据（API Key 或 OAuth 令牌） > 服务商对应的环境变量。
2. **OAuth 自动续期**：当存储的 OAuth 凭据即将过期时，`Models::get_auth` 自动调用该服务商注册的 `refresh_token` 回调并写回 `CredentialStore`；若网络续期失败，保留原凭据并返回 `ModelsErrorCode::OAuth`，防止网络抖动清空用户的登录态。
3. **动态目录刷新（`Models::refresh`）**：静态服务商直接返回内置模型表；动态服务商（如 OpenRouter 或后续接入的 CSTOA）先恢复本地 `ModelsStore` 缓存，在允许联网（`allow_network: true`）时并发拉取最新列表并原子更新缓存。
