# 使用情况遥测

发送端默认启用，同一会话统计发送到 CSTOA 与 Tim 的 `timserver_1`。两个接收端校验安装签名或 OA 凭据，并分别存储、确认。累计快照采用协议 `0.2`，兼容 `0.1` 最终记录。

回答结束、定时心跳、关闭及启动恢复共同触发保存与提交。字段仍按请求或会话实例累计；工具、模型、环境、上下文、错误和扣点共用提交入口。完整规则见[发送端](sender/SPEC.md#提交触发)。

实施状态见[改造计划](trigger-upgrade-plan.md)，生产服务未调整。心跳每 30 秒发送，接收端 90 秒未收到有效更新标记失联；失联不等于会话结束。协议、每日归属及在线状态保留期见[版本化提交](schema.md#版本化提交)。

安装身份独立于 OA 登录；两个接收端分别确认，队列写入使用跨进程锁。实机与运维的验证方法见[遥测测试](../test/telemetry.md#真实服务与环境验证)。

测试分工见[遥测测试](../test/telemetry.md)。账号姓名展示与遥测上传独立：安装与环境来自会话快照，OA 内省仅提供上传时的账号和登录标识。

## 运行条件

| 条件 | 行为 |
|---|---|
| `telemetry.json` 启用且配置端点 | 事件中累计，回答结束或心跳发现变化时提交累计快照，关闭时提交最终快照 |
| CSTOA 有效访问令牌 | 优先使用 OA 上传，学号与登录标识仅表示上传者 |
| 未登录、令牌过期或被拒 | 使用持久安装密钥签名上传，两端独立绑定公钥与确认 |
| 网络故障或服务端暂不可用 | 保留快照与队列，定时检查、启动、唤醒或网络恢复后补发；过期心跳不积压 |
| `enabled=false` | 不累计遥测、不订阅推理请求、不查询账单、不写遥测记录、不上传、不初始化安装身份、不探测系统；修改后重启生效 |

每个端点各有最多 200 条的独立待发队列，追加时淘汰最旧记录。一端失败或停采不影响另一端，单端点队列在启动时迁移到两端。

回答结束先落盘，再尝试上传；下一次提问沿用该实例继续累计。正常退出等待草稿链、有限账单查询和最终快照入队，不等待上传确认。

强制重启、强杀和拔盘依靠下次启动恢复已写草稿；关闭回调只作补充。已完成回答的快照可独立补发，写盘失败和队列淘汰仍有丢失边界。

CSTOA 使用独立的额度点汇总，附已观察／已确认请求数；未知扣点为 null，模型估算费用计入未定价。字段与覆盖限制见[会话记录](schema.md#cstoa-扣点)。

## 采集边界

只上传会话聚合统计；逐次请求记录保留在本地。字段与隐私边界由[信息收集契约](../contract.md)定义。报错原文是可能包含敏感片段的例外，服务端按保留期清理。
