# 遥测触发与心跳改造计划

改造按协议、回归测试、接收端、客户端、心跳、关闭恢复和发布七个阶段推进。协议、接收端快照更新、客户端准确确认、回答结束提交及多实例定时变化提交已实现并通过隔离测试。心跳调度、在线状态、关闭总预算、所有者证明恢复、页面辅助通知与本地诊断均已通过隔离测试。两个生产接收端已于 2026-10-27 更新并确认协议能力。客户端便携包发布和实机验收待执行。

触发规则见[发送端](sender/SPEC.md#提交触发)，Pi 事件含义见[发送端事件定义](sender/SPEC.md#pi-事件与消息字段)，在线判定见[接收端](receiver/SPEC.md#在线状态)。本页只规定实施顺序、改动位置和完成条件。

## 阶段与验收

各阶段先建立失败测试，再修改实现。改动按表内子项拆分，保持每次提交可验证。

| 阶段 | 交付 | 完成条件 |
|---|---|---|
| 0. 确认协议 | 定义版本、每日归属及在线状态保留期，更新契约、字段和双端请求／响应样例 | 快照身份、版本、更新授权、心跳、兼容、每日归属及保留期均有定义 |
| 1. 建立回归 | 真实 Web 会话、两个隔离接收端、可控时钟及终止恢复测试 | 能捕获草稿未入队、旧确认删除新版本、重复统计和失联误结束；不访问生产 |
| 2. 接收端快照更新 | 增量迁移、版本化写入、归属校验、逐快照确认、能力声明、汇总和导出 | 累计值更新且实例数不变；旧版本、重复和越权请求不改数据；已发布记录可读取 |
| 3. 客户端统一提交 | 分离活动统计、冻结快照与最终关闭；订阅 `agent_settled`；持久化版本及待发状态 | 后续提问继续累计；旧确认不删更新；部分入队失败可重试；网络和查账不阻塞提问 |
| 4. 心跳与在线状态 | 进程级运行身份及调度、定时变化提交、纯心跳、在线持久化和超时检查 | 可控时钟覆盖周期与超时；多会话只建一组任务；纯心跳不增加用量或查账 |
| 5. 关闭与恢复 | TUI 与 Web 关闭入口、辅助通知、跨机草稿归属、进程级退出预算 | 重复关闭可重试；多会话退出有总时限；强制终止及换机恢复保留原环境和活动时间 |
| 6. 联调与发布 | 跨仓库测试、实际 U 盘验证、双端备份与接收端先行发布 | 验收项目通过；两端同一快照一致；回退可保留队列与新增数据 |

协议定义见[版本化提交](schema.md#版本化提交)。已验证旧确认与更新并发、低版本入队、能力缺失、累计替换、更新归属、统计冻结、重复提交及最终快照部分入队重试。真实 Pi 的连续回答在两个本地接收端更新同一活动实例；心跳已验证双端独立、慢端合并、统计积压并行、序号、超时与关闭终态；关闭已验证实例入口绑定、并行预算、查账超时封存、同会话多实例隔离及跨进程所有者恢复；换机、拔盘和直接重启实测待执行。

## 涉及模块

客户端目录为 `agent/home/extensions/telemetry/`，接收端位于独立仓库 `cst-pilot-server`。保持 Pi 扩展边界，不修改官方可执行文件。

| 位置 | 调整 |
|---|---|
| 客户端 `index.ts`、`submission.ts` | 注册触发，分离回答提交与最终关闭，协调保存和入队 |
| 客户端 `collect.ts`、`record.ts`、`billing.ts` | 标记变化、固定统计边界、保持累计口径及未知值 |
| 客户端 `draft.ts`、`draft-owner.ts`、`file-lock.ts` | 持久化版本、恢复状态和实例归属，处理跨机与多进程 |
| 客户端 `outbox.ts`、`delivery.ts`、`transport.ts` | 版本合并、准确确认、逐端能力检查及发送调度 |
| 客户端 `shared.ts`、`close-budget.ts`、`config.ts`、`heartbeat.ts`、`diagnostics.ts` | 单组任务、运行身份、触发合并、诊断与禁用行为 |
| Web `index.ts`、`server/api.ts`、`server/session/sessions.ts`、前端 `data/telemetry-hints.ts` | 显式等待最终保存；页面提示只请求检查与补发 |
| 客户端 `test/` 与 Web `test/telemetry-shutdown.test.ts` | 事件、时钟、并发确认、关闭、恢复、TLS 和禁用测试 |
| 接收端 `src/` | 信封、鉴权、能力声明、SQLite 更新、在线状态、汇总与 Go 测试 |
| 接收端 `deploy/`、`scripts/` | 迁移、备份、双端更新、回退与受控状态查询 |

## 实施检查

1. 按 Pilot 实际 Pi 依赖核对事件字段，验证排队输入、失败和取消；不使用尚未提供的字段。
2. 网络任务与事件回调分离。快照固定后再查账和发送，避免下一次提问修改已提交内容。
3. 心跳与统计分别单飞发送，慢端心跳只保留最新待发状态，避免历史队列延迟在线更新。
4. 正常关闭使用进程级总预算，先保证本地保存；跨机恢复不能只凭 PID 判断原进程仍在运行。
5. 核对版本与失败类别的本地诊断状态，禁止写入凭据或敏感正文。

## 验证

测试项目和判定集中在[遥测测试](../test/telemetry.md#核对项目)。使用可控时钟覆盖心跳与超时，分别记录自动测试和 Windows 直接重启、U 盘拔插、跨机及网络恢复的实测结果。

关键并发场景为：旧确认与更新同时到达、最终关闭与定时提交重叠、恢复草稿落后于已确认版本。以上场景均须验证统计不回退、队列不误删、实例不重复计数。

## 发布与回退

1. 两个接收端已完成备份与发布，公网能力声明已验证，既有记录与原始 payload 保留，版本见[遥测部署](deployment.md#当前部署)。
2. 启用候选客户端，核对真实授权和双端上传；实际 U 盘验收通过后发布便携包。
3. 回退保留待发队列与新增数据库内容，执行步骤见[遥测部署](deployment.md#触发与心跳改造发布)。

客户端发布、数据库恢复和用户 U 盘补发分别确认后执行。
