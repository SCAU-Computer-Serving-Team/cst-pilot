# 接收端

接收端校验上传凭据、保存会话统计，提供命令行导出和删除。支持最终记录协议 `0.1` 和累计快照协议 `0.2`，字段见[信息收集契约](../../contract.md)和[会话记录](../schema.md)，部署见[部署说明](../deployment.md)。

回答结束、定时心跳与关闭均可提交累计快照，接收端须保持一个实例一份最新有效统计。在线状态与使用统计分别保存；快照更新和心跳在线状态已实现，关闭联调与双端发布待完成，见[改造计划](../trigger-upgrade-plan.md)。

## 接口

| 接口 | 行为 |
|---|---|
| `POST /v1/sessions` | 上传最多 50 条会话记录，完整正文最多 1 MiB；`0.2` 纯心跳允许空数组 |
| `GET /v1/sessions` | 声明协议与能力；不返回记录 |
| `GET /healthz` | 返回 ok、会话条数、version、builtAt；数据库不可读时失败 |

公网入口将 /api/telemetry 转发到 /v1/sessions，不提供读记录或下发指令的接口。

新增协议须明确声明支持能力，客户端逐端确认后再发送。心跳与快照分别确认，心跳成功不代表统计已保存；纯心跳的空记录规则随新协议定义，`0.1` 继续要求非空记录数组。

| 响应 | 发送端处理 |
|---|---|
| 202 | `0.1` 返回 `{ accepted, rejected, reasons }`；`0.2` 增加逐版本 `acks`，见[版本化提交](../schema.md#版本化提交) |
| 401 | 凭据或签名无效，保留记录 |
| 403 | OA 吊销、改密，或安装已绑定其他公钥，保留记录 |
| 400 / 413 | `0.1` 丢弃该批；`0.2` 未得到逐项确认时保留 |
| 429 | 限流，保留并重试；不写该请求的上传日志 |
| 5xx | 服务或身份服务故障，保留并重试 |

## 在线状态

每个接收端独立维护运行实例的最后心跳、客户端报告的活动状态、心跳序号及超时状态。默认心跳间隔 30 秒，失联阈值 90 秒；使用服务端接收时间判定，客户端时间仅作活动参考。

| 状态 | 判定与动作 |
|---|---|
| 在线 | 收到通过鉴权、归属及顺序校验的当前心跳；记录服务端接收时间 |
| 失联 | 距最后有效心跳达到 90 秒，保留最后统计并标记不可联 |
| 已关闭 | 收到该运行实例明确的正常关闭状态；与会话删除、单个实例结束分别处理 |
| 恢复在线 | 失联后收到更新心跳；相同进程继续原运行 ID，重启生成新的运行 ID |

1. 默认每 15 秒检查一次超时；连续失联时只记录一次状态变化，状态读取同时核对截止时间。接收端重启后依据持久化时间重新判断。
2. 重复、倒序心跳不延长在线时间；已正常关闭的运行实例保持关闭。历史统计补发与历史关闭记录不恢复原进程在线状态。
3. 超时只改变在线状态，不生成最终用量、不写 `endReason=crash`，也不把等待超时的时间计入会话或工作时长。服务端无法获取客户端未上传的数据。
4. 心跳可以携带有变化的快照，也可只有在线状态；心跳确认与统计确认分别校验。空记录信封、版本字段和鉴权绑定见[版本化提交](../schema.md#版本化提交)。
5. 最新在线状态不包含对话、工具正文、凭据或 PID；不逐次保存完整心跳正文，状态保留期见[心跳信封](../schema.md#心跳信封)。

两个接收端可能显示不同在线状态，不据一端超时修改另一端，也不通过两端关联推断具体自然人。在线状态通过受控运维查询核对，不增加公开读取或命令下发接口。

## 身份解析

### OA 凭据

Bearer 访问令牌由接收端向 OA 内省，取 mid 和 device_id。服务凭据仅放服务器，接口不跟随重定向；OA 服务不可用返回 503，不缓存故障。

| 内省结果 | 处理 |
|---|---|
| active=true 且包含 mid、device_id | 写入上传者 mid、deviceId |
| expired / invalid | 401 |
| revoked / password-changed | 403 |
| 非 200、解析失败或超时 | 503 |

正常结果按令牌 SHA-256 缓存 60 秒，仅保存在内存，不写令牌或哈希日志。不额外校验模型调用作用域。

### 安装签名

未登录使用 Installation 鉴权及 Ed25519 签名，格式见[发送端](../sender/SPEC.md#凭据与配置)。首次有效签名自动绑定公钥；后续必须保持相同公钥，服务重启不解除绑定。

1. 签名覆盖安装标识、时间和正文摘要，时间允许前后 10 分钟；先验签，再注册安装。
2. 每个安装每分钟最多 60 次、每个连接来源每分钟最多 120 次；内存计数有界。通过反向代理时同一连接来源限额由该入口共享，不能把它当真实用户 IP 限流。
3. 记录声明的非空 installationId 必须与安装鉴权一致，否则逐条拒收。无新增身份的记录允许兼容接收。
4. 安装签名只证明持有密钥，无法阻止创建多个新安装。自然人认证、恶意批量注册告警与密钥遗失处理需独立管理。

### 归属边界

mid、deviceId 在数据库列和 payload 中均由本次上传凭据确定，匿名上传的 payload 为 null。客户端提供的同名字段覆盖清除；这两个字段只表示上传者，不据此确定排队会话的操作人。

identity 和环境保持客户端会话快照；相同快照重传保留首次归属、环境和接收时间。后续更新须校验原实例归属，禁止其他上传者凭 recordId 覆盖记录；首次接收时间与更新接收时间须可区分。

匿名安装、系统环境和上传账号分别统计。累计快照的版本、更新授权与兼容规则见[版本化提交](../schema.md#版本化提交)。

## 校验

整批拒绝：鉴权失败、无效 JSON、records 非数组、超过 50 条或正文超过 1 MiB。空数组仅允许带心跳的 `0.2` 信封；无效心跳单独拒收，不撤销有效统计快照。

| 逐条检查 | 拒收原因 |
|---|---|
| v 属于支持集合：0.1、0.2 | unknown-version |
| 0.2 revision 为正安全整数，final 与 endReason 一致 | bad-revision、bad-final-state |
| type=session | unknown-type |
| recordId 非空字符串且最多 64 字符 | bad-record-id |
| tools≤512、models≤32、errors≤10 | too-many-elements |
| 安装鉴权与记录非空安装标识不匹配 | installation-mismatch |

基础计数字段类型不符按 0，缺少数组按空数组；新增环境、CSTOA 扣点和 usage 完整性字段缺失时保持未知。扣点汇总类型、范围或计数关系非法时，派生扣点列整体置 NULL；原始字段保留在 payload，不以业务合理性检查拒收。

receivedAt 使用服务端时钟；ip 来自连接，IPv4 存 /24 网段。经过反向代理时记录连接来源，不能作为会话地点或用户识别依据。

## 存储

使用 Go、纯 Go SQLite、单数据库文件和 WAL。原始 payload 与派生列在同一事务中保存，record_id 为去重主键；新增字段迁移增加派生列与索引，不改已有原始记录。

| 表 | 内容 |
|---|---|
| sessions | 会话正文、上传者、接收时间、网段、统计、费用及环境派生列 |
| installations | 安装 ID、绑定公钥、首次注册时间；不保存私钥或原始 MachineGuid |
| process_runs | 运行 ID、安装与环境、最新序号及状态、服务端接收及状态变化时间、最近活动与快照版本 |
| devices | 有 OA 登录标识的最近接入信息，匿名上传不创建空设备行 |
| members | 编号到姓名与队伍的展示资料，独立于鉴权，不强制外键 |
| daily_rollup | 按接收时间 +08:00 日期、上传者 mid、installation_id、environment_id 聚合 |
| uploads | 请求结果、条数、拒收原因、插入数、状态与耗时，不含正文、令牌、签名或密钥 |

sessions 增加 snapshot_revision、snapshot_final、owner_installation、updated_at；首次接收时间与上传者保持不变，CSV 增加版本、最终状态和更新时间。process_runs 按运行 ID 更新，安装与环境绑定不变；定时超时只更新状态，不改 sessions。

sessions 新增派生列：installation_id、environment_id、environment_source、os_platform、os_name、os_display_version、os_is_pe、runtime_version、runtime_arch。未知值为空；已有 os_version、os_arch、admin 继续保存，payload 区分 null 和缺失。

sessions 与 daily_rollup 增加可空派生列：

| 列 | 来源与口径 |
|---|---|
| cstoa_requests | cstoaBilling.requests |
| cstoa_settled_requests | cstoaBilling.settledRequests |
| cstoa_quota_points | 已确认额度点之和；无确认账单为 NULL |
| incomplete_usage_turns | models[].incompleteUsageTurns 已知部分之和；完全缺失时为 NULL |

首次迁移从原始 payload 重算新列及费用派生列，CSTOA 统一计入 unpriced_turns，原始 payload 保持不变。每日汇总只累加已知部分，全部未知仍为 NULL；额度点须与请求覆盖数量一起读取。CSV 导出包含上述四列。

索引覆盖接收时间与上传者、OA 登录标识、会话 ID、工具包版本、安装及环境。不同币种分别汇总，未定价单列；峰值与窗口成对保存。缺失标识只参与未知组统计，不计为一个已识别用户。

汇总不保存报错原文。累计快照更新须同步替换 payload 与派生值，汇总按实例最新有效快照计算，不能把各次累计值再次相加。每日归属保持首次接收的 +08:00 日期，见[版本化提交](../schema.md#版本化提交)。

结构变化时可清空派生汇总并从 sessions 重建，原始会话保留。

## 保留期

| 内容 | 保留与清理 |
|---|---|
| 会话统计、身份、公钥与汇总 | 长期保存 |
| sessions.payload.errors | 180 天后移除 |
| uploads | 90 天后删除 |
| 每次运行的最新在线状态 | 最后接收超过 90 天后删除，不保存逐次心跳正文 |

启动及每 24 小时清理、重算汇总。模型报错原文可能含路径或账号，备份同样遵循原文保留边界。

## 运维接口

| 命令 | 用途 |
|---|---|
| export-csv | 导出会话派生列，包含新身份、系统名称和运行时字段，不导出报错正文 |
| rollup | 重算每日汇总 |
| delete --mid / --device / --installation | 按上传账号、OA 登录标识或匿名安装删除会话，再重算汇总 |

命令行操作显式指定 TELEMETRY_DB。按安装删除会话仍保留公钥绑定，避免其他密钥重新占用同一标识；安装密钥恢复需独立运维流程。部署不开放远程删除接口，验证方法见[遥测测试](../../test/telemetry.md)。
