# 接收端

状态：设计稿，契约版本 0.1。更新：2026-09-20。字段见 [schema.md](../schema.md)。

## 结论

1. 第一版只做两件事：收记录，写数据库。看板与告警后置。
2. 一场会话一条记录，原始记录整体存 JSON，不拆明细表。
3. 部署在队伍自己的服务器或云主机，不引入第三方 SaaS。
4. 不做用户管理。身份由队员的 OA 登录决定，接收端验令牌取 `mid` 与 `device_id`，见 [../../contract.md](../../contract.md)「身份来源」。

## 接口

```
POST /v1/sessions
Authorization: Bearer <OA 访问令牌>
{ "v": "0.1", "batchId": "<uuid>", "sentAt": "...", "records": [ ... ] }
```

| 响应 | 含义 |
|---|---|
| 202 `{ accepted, rejected }` | 收下整批；`rejected` 里是校验不过的条目 |
| 401 | 令牌无效或过期 |
| 403 | 无权限或设备被吊销 |
| 400 / 413 | 请求本身不合法（格式错误，或超过 1 MB） |
| 429 / 5xx | 限流或服务端故障，可重试 |

发送端对每个响应的处理见 [sender/SPEC.md](../sender/SPEC.md)「结果分类」。

约定：单批上限 50 条或 1 MB；接收端从 `Authorization` 头取令牌，验签后把 `mid` 与 `device_id` 写进每条记录，令牌无效的请求不入库；逐条校验，非法条目进 `rejected`，不拒绝整批；接收时间与来源 IP 由服务端补充；`GET /healthz` 返回进程与数据库状态。

去重方式见议题 R15。

## 存储

| 表 | 主键 | 内容 |
|---|---|---|
| `devices` | `device_id` | 首次与最近上报、系统与版本。限流与删除的单位 |
| `members` | `mid` | 队员编号到姓名、队伍的翻译，由 OA 导出同步 |
| `sessions` | `record_id` | 会话记录。公共字段建列，`models[]` 与 `tools[]` 进 JSON 列 |
| `daily_rollup` | `(date, mid)` | 每日聚合，报表只读这张表 |
| `upload_log` | `batch_id` | 批次去重与来源 IP，按保留期清理 |

`members` 只做翻译，不做鉴权也不做外键强制。库里没有的 `mid` 照常入库，报表直接显示编号，不丢数据。

## 选型候选

| 方案 | 优点 | 代价 |
|---|---|---|
| A 单进程 + SQLite | 部署最简，备份即拷文件 | 数据量大后查询变慢 |
| B Postgres + 看板 | 查询强，看板现成 | 运维成本高 |
| C Serverless + 托管库 | 免运维 | 依赖第三方 |
| D 只落 JSONL 文件 | 实现最快 | 无查询能力 |

建议先做 A，接口与表结构按本文件设计，需要时换 Postgres。最终见议题 R2。

## 报表需求

每人每日 token 与费用、模型使用分布、工具调用次数与失败率、会话数与时长、版本与系统分布、来源地区。先做哪些见议题 R3。

## 安全与运维

| 项 | 要求 |
|---|---|
| 传输 | 只用 HTTPS |
| 鉴权 | 上传用队员登录的 OA 访问令牌，与模型调用同一个。校验方式见议题 R4 |
| 限制 | 请求体上限 1 MB，按 `device_id` 限流 |
| 写入 | JSON 入 JSON 列，不拼 SQL |
| 保留期 | 记录与批次日志到期删除，见议题 R5 |
| 删除 | 支持按设备或队员删除该来源全部数据 |
| 备份与监控 | 定期备份数据库；监控进程存活、磁盘水位、请求失败率 |

记录里不含对话内容与路径原文，但报错原文可能回显路径、账号或请求片段，仍可推断使用习惯，保留期与访问范围需明确规则。

| 编号 | 议题 | 候选 |

| R5 | 保留期 | A 明细 90 天、聚合永久。B 1 年。C 全部永久 |

| R13 | 运维归属 | 谁负责部署、备份与恢复 |
| R14 | 队员翻译表怎么维护 | A 人工维护。B 由 OA 导出同步（与 `mid` 同源，优先） |
