# 发送端规格

发送端在 Pi 内累计使用统计，在回答结束、定时心跳、关闭及启动恢复时统一保存、提交，同一快照写入各接收端的独立队列。字段见[信息收集契约](../../contract.md)和[会话记录](../schema.md)，验证方法见[遥测测试](../../test/telemetry.md)。

本文规定目标触发机制，实施状态与执行步骤见[改造计划](../trigger-upgrade-plan.md)，快照更新协议见[版本化提交](../schema.md#版本化提交)。

## 采集边界

1. TUI 与 Web 使用相同统计规则，每个会话实例独立累计。请求、工具、模型用量、环境、上下文、错误与扣点共用本页定义的提交触发机制。
2. 事件采集不等待网络请求，不保存对话和工具正文。CSTOA 账单查询只读本地对应凭据，不上传凭据；模型请求报错原文按契约保存。
3. 会话启动时异步初始化安装身份并探测系统，草稿和提交快照使用该实例的结果。探测失败的属性为 `null`，补发不重新探测。
4. 安装标识及密钥只写 `agent/home/telemetry/identity.json`，多进程初始化共用同一文件锁。已有文件损坏时不重建；首次无法持久化时身份保持未知。
5. Windows 只读取系统名称、功能版本、原生架构、PE、权限及 MachineGuid。原始 MachineGuid 仅在内存中参与 HMAC，PE 或来源不可靠时不生成环境标识。
6. `cost` 与 `currency` 同源，时间使用带时区偏移的 ISO 8601，工具包版本读取失败为空字符串。

## 事件与统计

| 事件 | 统计 |
|---|---|
| `session_start` | ID、开始原因、时间、通道及独立环境快照；先恢复可确认已终止实例的草稿 |
| `input` | `interactive` 或 `rpc` 来源的提问次数 |
| `before_provider_request` | 请求开始时的思考强度 |
| `turn_start` / `turn_end` | 累计活动时长、轮次、模型用量、费用、上下文峰值、中断与错误；结束后保存恢复草稿 |
| `agent_settled` | 本次自动处理结束，统一冻结、保存并提交累计快照 |
| 心跳到期、启动、唤醒、网络恢复提示 | 检查未提交变化与待发队列，保存需要更新的统计，并向各端发送当前在线状态 |
| `after_provider_response` | 非 2xx 响应的状态码计数；轮次出错且未收到响应时计网络错误 |
| `tool_call` | 工具名与 scope，省略时使用工具默认 scope |
| `tool_execution_start` / `tool_execution_end` | 配对累计次数、失败、耗时、结果字节数、降级与裁剪 |
| `session_compact` / `session_compact_failed` | 压缩次数、压缩前 token、溢出原因及失败次数 |
| CSTOA 推理 HTTP 开始／响应 | 记录请求尝试与网关请求 ID，异步保存草稿；不读取响应正文 |
| 实例结束 | 固定结束时刻、原因与上下文条目数；保存并提交最终快照 |

同一次工具调用的每项指标最多计一次。

| 指标 | 来源 |
|---|---|
| 降级 | `sys`、`driver`、`eventlog` 的 `details[scope].degraded`；startup、bitlocker 对应包装的标记；disk 顶层标记、`usage.method=node-walk` 或非空 `usage.degradedFrom` |
| 裁剪 | 诊断结果的 `outputTruncated`；内置 bash 的 `details.truncation.truncated`，缺少标记时不推测 |
| 命令条数 | `runbook.items` |
| 搜索服务与抓取方式 | web_search 的 providers、fetch_content 的 modes |

## Pi 事件与消息字段

Pilot 当前依赖 Pi `0.85.1`，`agent_settled` 只有 `type` 字段。该事件表示自动重试、压缩恢复和排队续答已处理完毕，结果可以是成功、失败或取消；一次通知可覆盖多次排队输入。

| 事件 | 边界与字段 | 采集要求 |
|---|---|---|
| `message_end` | 一条消息结束，字段为 `message`；用户消息和工具结果也触发 | 回调早于消息写入 SessionManager，读取事件中的消息；助手消息结束时工具可能尚未执行 |
| `tool_execution_end` | 一个工具返回，含 `toolCallId`、`toolName`、`result`、`isError` | 累计工具指标 |
| `turn_end` | 模型响应及其工具批次结束，含 `turnIndex`、`message`、`toolResults` | 此时消息已追加；累计轮次并保存草稿 |
| `agent_end` | 当前 Agent 循环结束，含 `messages` | 会话层仍可能重试、压缩或继续处理排队输入 |
| `agent_settled` | 本次自动处理结束 | 直接订阅并提交累计统计，保留活动实例 |
| `session_shutdown` | 当前扩展实例正常销毁，含 `reason`、可选 `targetSessionFile` | 提交最终快照；强杀和重启可能没有通知 |

`turnIndex` 在每次 `agent_start` 后从 0 开始。提问按 `input` 来源统计，轮次按 `turn_end` 累计，会话数按实例统计。

| 消息字段 | 含义 |
|---|---|
| `stopReason` | Pi 统一的单条模型响应结束原因，见下表 |
| `rawStopReason` | 可选的供应商原始结束原因 |
| `endTurn` | 可选的供应商结束标记，仅供调试；缺失保持未知，Pi 当前不据此控制流程 |

| `stopReason` | 含义 |
|---|---|
| `pending` | 仍在生成 |
| `stop` | 单条响应正常结束，仍可能处理排队输入 |
| `toolUse` | 返回工具调用，后续执行工具并可能继续请求模型 |
| `length` | 达到输出长度限制 |
| `error` | 请求失败，可能自动重试 |
| `aborted` | 响应被取消 |
| `deferred` | 返回可后续取回结果的句柄 |

典型顺序为 `input → agent_start → message_end → 工具执行 → tool_execution_end → turn_end → message_end → turn_end → agent_end → 会话层检查 → agent_settled`。重试可产生多次 `agent_end`，最终只通知一次 `agent_settled`；`text_end`、`thinking_end` 只表示内容块结束。

SDK 的 `session.subscribe()` 在 `agent_end` 上补充 `willRetry`，扩展不提供此字段；它只描述重试判断。事件回调会被 Pi 等待，远端上传和长时间查账须在后台执行。

`AgentSession.dispose()` 不派发 `session_shutdown`，Web 运行层须显式提交。Pi 宿主处理 SIGTERM、SIGHUP 等可处理信号并进入关闭流程；扩展不接管进程信号。当前依赖未提供独立的 Windows 系统关闭事件，紧急退出及未捕获异常可能直接结束进程。

本地 Pi `1.4.0` 另有 `agent_before_settle` 和 `agent_settled.aborted`；后者为 false 仍可能失败。升级依赖后再验证这些字段。

核对入口为安装包的 `core/extensions/types.d.ts`、`core/agent-session.js`（`_runAgentPrompt`、`_handlePostAgentRun`、`_emitAgentSettled`）、`core/agent-session-runtime.js`，及其依赖的 `pi-agent-core/dist/agent-loop.js`、`pi-ai/dist/types.d.ts`。

## 提交触发

全部触发进入同一提交入口，按实例串行处理；统计有变化或实例结束时才生成更新快照。回答完成、定时提交、正常关闭与启动恢复均可独立保存已有数据，心跳不依赖浏览器页面保持打开。

| 触发 | 时机与动作 |
|---|---|
| 中间检查点 | HTTP 开始／响应、`turn_end` 保存恢复草稿 |
| 回答完成 | 收到 `agent_settled` 后立即保存、入队并尝试上传 |
| 定时心跳 | 每 30 秒检查所有活动实例；有变化则保存并入队，同时发送当前在线状态；长任务与空闲均运行 |
| 正常关闭 | TUI 切换／退出、Web 删除／退出与运行层关闭提交最终状态 |
| 关闭通知 | 可处理的终止信号、系统关闭通知和页面离开提示尽力触发保存 |
| 启动恢复 | 恢复终止实例的草稿与未确认快照，再发送新运行实例的心跳 |
| 唤醒或网络恢复 | 提示到达或定时任务检测到间隔中断后，立即检查补发；合并错过的心跳，不逐次补发 |

页面的 `pagehide`、`pageshow`、`online` 经同源 `POST /api/lifecycle/telemetry` 请求检查和当前心跳，两秒内的提示合并。离开通知使用 keepalive，页面事件不结束进程或任何会话。定时检查和启动恢复独立工作；网络故障不阻塞后续提问。

## 心跳

使用普通 HTTPS 请求，向两个接收端分别发送，默认间隔 30 秒。每个 Pi 进程、home 只维护一组定时任务，多会话和扩展重载复用该任务；定时器不阻止进程退出。进程阻塞或休眠可延迟心跳，恢复后合并错过的触发并立即检查。

| 内容 | 规则 |
|---|---|
| 运行身份 | 每次进程启动生成运行实例 ID，关联已有安装与环境标识；多个程序分别识别，PID 只在本地使用 |
| 在线状态 | 报告空闲、处理中或正常关闭；在线仅表示发送进程近期可联 |
| 活动与快照 | 携带最后已知活动时间及快照版本；有变化时提交相应累计统计 |
| 顺序 | 同一运行实例的心跳带递增序号，服务端忽略重复或倒序的在线更新 |
| 网络失败 | 过期心跳丢弃；统计快照先持久化再重试，独立维护各端确认 |
| 恢复连接 | 发送当前运行实例的最新心跳，补发历史统计；历史补发不恢复原进程的在线状态 |
| 纯心跳 | 不新增会话、快照版本、模型用量或工作时长，也不触发额外账单查询 |
| 鉴权与禁用 | 复用安装签名或 OA 鉴权及 TLS 验证；禁用遥测时不生成运行身份、不发送心跳 |

心跳与统计使用独立发送任务，每个端点各自单飞。慢端等待中的心跳只保留最新一份，统计积压不阻塞在线更新；纯心跳不写持久队列。信封与能力协商见[版本化提交](../schema.md#版本化提交)。

正常关闭的最终统计持久化入队，关闭状态尽力发送。关闭通知未送达时，接收端按超时标记失联；在线判定见[接收端](../receiver/SPEC.md#在线状态)。

## 回答结束与关闭

本页以 `agent_settled` 作为回答结束的提交事件，成功、失败和取消均保存已发生的用量。该事件可能覆盖多次排队输入，提问数、模型轮次和会话数分别统计。

事件字段与执行顺序见[Pi 事件与消息字段](#pi-事件与消息字段)。提交后保留活动实例，最终关闭单独处理。

| 触发 | 提交与生命周期 |
|---|---|
| TUI 退出、new、resume、fork、reload | `session_shutdown` 提交被关闭实例的最终快照，保留对应结束原因 |
| Web 删除会话、退出程序、正常关闭运行层 | 运行层显式等待该实例最终快照入队，再销毁实例 |
| 页面刷新、切换、关闭标签页 | 尽力请求保存当前快照；实例可继续运行，其他标签页不受影响；不依赖浏览器离开通知保证提交 |
| 可处理的终止信号或系统关闭通知 | 尽力执行有界的最终保存与入队；通知可能缺失或被系统提前终止 |
| 强制重启、强杀、断电或拔盘 | 下次启动恢复已保存草稿及待发快照，按 `crash` 补齐未关闭实例的最终状态 |

关闭、回答结束和恢复可以重复到达，提交必须串行、可重试，不重置累计值或重复统计。正常关闭只等待本地保存、有界查账和入队，不等待服务器确认。真实退出的遥测等待预算为 5 秒，同一 home 的 TUI 与 Web 实例共用截止时刻。Web 批量定稿并行启动；单次删除或切换使用独立预算，不发送进程关闭心跳。超时后停止等待，本地任务继续尽力保存；进程提前终止时依赖最后成功保存的草稿。

## 会话与草稿

| 场景 | 规则 |
|---|---|
| 请求与轮次 | HTTP 开始／响应及轮次结束保存恢复草稿，保留最后已保存活动时刻；草稿写入串行执行 |
| 回答结束 | 固定边界并冻结统计，先保存并入队，再后台有限查账；账单变化形成新版本，保留活动实例草稿 |
| 最终关闭 | 提问、轮次和请求尝试均为零时不产记录；其余先保存带结束状态的快照，全部端点入队成功后清理实例草稿 |
| 后续提问 | 沿用实例继续累计；冻结快照不受后续事件或异步查账修改 |
| 定时提交 | 复用回答结束的快照保存与入队入口，保留活动实例草稿；纯在线更新不修改统计截止时间 |
| 启动恢复 | 本机所有者证明仍有效时跳过草稿；不以 PID 判存活。未关闭实例按 crash 恢复，结束取最后已保存活动时刻；已关闭快照保留原原因与时间 |
| 恢复失败 | 查账后的恢复结果先封存，再写端点队列；部分入队失败重用相同版本和内容。启动及 30 秒检查重试，全部目标入队后才清理草稿 |
| 正常退出 | 等待草稿链、有限账单查询及最终快照入队，不等待上传确认；已有网络任务可能被进程退出中断 |
| 强杀 | 已提交回答可独立补发；未提交部分依赖最后已写草稿，未完成轮次的 usage 可能缺失 |

草稿按 `recordId` 分文件，同一 sessionId 的恢复实例独立保存。所有者证明只存本地，由进程内核资源校验；Windows 使用随机命名管道，其他平台使用随机回环端口，进程退出自动释放。不提供远程访问或命令接口，上传不含此证明。

| 通道 | 开始原因 | 结束原因 |
|---|---|---|
| TUI | startup、new、resume、fork、reload | quit、new、resume、fork、reload、crash |
| Web | new、resume、fork | quit、delete、crash |

## CSTOA 账单查询

`oauth/request-observer.ts` 仅在启用遥测且订阅当前 sessionId 时包装 CSTOA 推理 fetch。每次实际 HTTP 尝试分别记录；从 `x-oneapi-request-id` 取请求 ID，不改变推理正文或等待查询。

1. `billing.ts` 只读 auth.json 中有效 CSTOA OAuth 访问令牌或 APIKEY，向固定 OA 地址 `POST /api/agent/llm/billing` 查询，每批最多 50 个 ID。安装签名不能查账，不刷新或写回凭据。
2. 每次查询超时 2 秒，禁止重定向。回答结束先保存并入队，后台查账总限为 4.5 秒；变化通过新快照提交。关闭先保存固定结束时刻的检查点，补查服从关闭的统一预算；未全确认时隔 300ms 再查一次。预算到期封存已知结果，不等待已有后台查账任务的独立时限。定时提交复用已知扣点，心跳不查询账单。
3. 活动实例的未知账单可在后续回答结束或关闭时补查并形成新快照。启动恢复可对未关闭草稿补查一次，使用 4.5 秒总限；已入队快照保持原内容，缺少有效 ID 时不发查询。
4. 查询失败保留未知，不阻塞推理、不输出凭据。请求 ID 仅存在本地草稿；上传对象只含[扣点汇总](../schema.md#cstoa-扣点)。两端收到同一份快照。

## 队列与发送

每个端点使用独立 JSONL 队列，上限 200 条，超限淘汰最旧记录。同一快照重试保持身份与内容；同一实例的更新须可区分先后，不能被旧快照确认删除。版本字段与兼容规则见[版本化提交](../schema.md#版本化提交)。

追加、确认删除、草稿事务与身份初始化使用目录锁，兼容 FAT/exFAT；锁内不执行远端查询。锁的本机所有者证明失效后可回收，复制介质后的 PID 碰撞不阻止回收。

1. 回答结束、定时心跳、关闭、启动恢复及唤醒或网络恢复提示触发检查、入队与发送；定时任务同时重读凭据、重试未入队快照与待发队列。快照继续按实例累计，定时器不强制切分会话。
2. 同一进程、home、端点分别只运行一个统计发送任务和一个心跳发送任务，其他触发合并。不同进程可能重发，服务端去重；确认只作用于实际发送的快照。
3. 原 pending.jsonl 先复制至所有目标，再清除源记录；端点移除后保留其队列。
4. 每批最多 50 条、记录正文合计不超过 900 KiB。单条大于 1 MiB 不入队，超出发送预算的记录整条移除，不裁剪报错文本。
5. 写入失败保留已有文件，容量淘汰、未落盘轮次和强杀仍有数据丢失边界。

| 结果 | 行为 |
|---|---|
| 202 | `0.2` 校验逐版本确认与明确的永久拒收原因；缺失或不匹配时保留。`0.1` 按整批确认；均只删除实际发送的内容 |
| 401 / 403 | 保留队列；OA 凭据被拒时尝试安装签名 |
| 400 / 413 | `0.1` 丢弃该批；`0.2` 未获逐版本确认时保留 |
| 429 / 5xx / 网络错误 / 超时 | 保留队列，等待后续触发或 30 秒重试 |
| 404 / 410 | 本进程停止该端点发送，保留队列 |
| CA 缺失或 TLS 错误 | 保留队列，不降低证书验证 |

单次网络超时 5 秒，不跟随重定向。采集和发送失败不影响诊断，不输出凭据。

## 诊断状态

`telemetry/status.json` 记录最近保存、逐端入队与确认版本、最近成功心跳及失败类别。最多保留 50 个保存引用、8 个端点，各端最多保留 20 个入队引用及 20 个确认引用；确认区分服务端接受与永久拒收。

端点仅保存 URL 摘要，失败只保存分类和时刻，不写鉴权、原始地址、响应正文或系统标识。状态是有界诊断记录，不能代替草稿和队列；禁用遥测时不更新。

## 凭据与配置

有效 OA 凭据优先，只读 auth.json，不刷新或写回；缺少、过期或被拒时使用安装签名。mid 和 deviceId 仅表示本次上传者，不能回填为历史会话操作人。

安装签名采用 Ed25519。32 字节种子由 `HMAC-SHA256(identityKey, UTF-8("upload-signing"))` 派生，与环境标识的用途分离；服务端首次收到有效签名时绑定安装与公钥，不接收密钥原文。

| 鉴权头 | 内容 |
|---|---|
| `Authorization` | `Bearer <OA访问令牌>` 或 `Installation <installationId>` |
| `X-Telemetry-Installation` | `0.2` 使用 Bearer 时指定签名安装 |
| `X-Telemetry-Key` | 安装公钥的 DER/SPKI，base64url，无填充 |
| `X-Telemetry-Time` | Unix 毫秒字符串，接收端允许前后 10 分钟 |
| `X-Telemetry-Signature` | 对签名原文的 Ed25519 签名，base64url，无填充 |

签名原文为以下四项用换行连接，不加末尾换行：`telemetry-upload`、installationId、时间头原文、请求正文原始 UTF-8 字节的 SHA-256 小写十六进制。`X-Telemetry-Key`、`X-Telemetry-Time`、`X-Telemetry-Signature` 用于安装签名；`0.2` 同时携带 Bearer 时仍须签名；重试重新签名，记录内容与 recordId 保持。

安装签名只证明密钥持有权，不证明自然人或物理电脑真实性。系统时钟偏差超过窗口时保留队列，校时后重试。

`agent/home/telemetry.json`：

```json
{
  "enabled": true,
  "endpoints": [
    { "url": "https://www.cstoa.top/api/telemetry" },
    { "url": "https://8.163.28.9:8445/api/telemetry", "caFile": "timserver_1.crt" }
  ],
  "authProvider": "cstoa"
}
```

配置启动时加载，修改后重启。enabled=false 不采集、不订阅 CSTOA 请求、不查询账单、不初始化身份、不探测系统、不写队列、不上传。公网端点必须 HTTPS，回环测试允许 HTTP；拒绝 URL 中的用户名、密码与片段。

caFile 仅用于对应端点，继续校验证书链、有效期与主机名。币种见[契约](../../contract.md#计费币种)。发行配置由 pack/release-settings.mjs 维护，白名单装配排除 telemetry/ 运行目录；Pi 自带遥测另由 PI_OFFLINE 与 enableInstallTelemetry=false 关闭。
