# 发送端规格

发送端在 Pi 会话内采集统计，同一记录写入各端点的独立队列。契约版本为 0.1。

字段与隐私边界见[信息收集契约](../../contract.md)和[统计口径](../schema.md)。模块与运行设计见[系统架构](../architecture.md)，验证状态见[遥测验证](../../test/telemetry-report.md)。

## 采集边界

1. TUI 与 Web 使用相同的统计规则，每个会话实例独立累计。
2. 采集器只更新内存，不读取凭据、不计算设备标识、不执行同步文件或网络操作。采集失败跳过本次累计，不影响诊断。
3. 不采集对话、工具参数或工具输出正文。模型请求的报错原文按契约规定收集，每组保存完整文本和次数。
4. `cost` 与 `currency` 一起记录。币种映射缺少服务时使用 `USD`；映射文件不可读或无效时，币种留空。
5. 时间使用带本地时区偏移的 ISO 8601。`kitVersion` 从工具包读取，读取失败时留空。
6. 管理员探测异步执行，采集事件不等待。结果未就绪时按非管理员记录，定稿时等待探测结果。

## 事件与统计

| 事件 | 统计 |
|---|---|
| `session_start` | 会话 ID、开始原因、时刻与通道；上一会话未结束时，先按 `crash` 定稿 |
| `input` | 来源为 `interactive` 或 `rpc` 时累计提问数 |
| `before_provider_request` | 保存本次请求的思考强度；缺失时保持未知 |
| `turn_start` / `turn_end` | 累计活动时长、轮次、模型用量、费用、上下文峰值、中断和错误；结束后保存草稿 |
| `after_provider_response` | 非 2xx 响应累计供应商错误；本次请求没有响应时才计网络错误 |
| `tool_call` | 保存工具名和 `scope`；省略时使用工具默认值 |
| `tool_execution_start` / `tool_execution_end` | 按调用 ID 配对，累计次数、失败、耗时、结果体积、降级与裁剪 |
| `session_compact` | 累计压缩次数、压缩前 token 与溢出触发次数 |
| `session_compact_failed` | 只计失败次数，不收集错误正文 |
| 会话实例结束 | 补充结束时刻、原因与上下文条目数，写入全部端点队列 |

工具结果按实际包装读取，同一次调用的每项指标最多计一次。

| 指标 | 取值 |
|---|---|
| 降级 | `sys`、`driver`、`eventlog` 的 `details[scope].degraded`；`startup` 的 `details.startup.degraded`；`disk` 顶层标记、`usage.method=node-walk` 或非空 `usage.degradedFrom` |
| 裁剪 | 诊断工具文本中的 `outputTruncated`；内置 `bash` 的 `details.truncation.truncated`。缺少结构化标记的其他工具不计 |
| 命令条数 | `runbook.items` |
| 搜索服务与抓取方式 | `web_search` 按服务统计，`fetch_content` 按方式统计 |

## 会话与草稿

| 场景 | 规则 |
|---|---|
| 轮次结束 | 将累计状态重写为会话草稿，记录最近一次 `turn_end` 时刻；同一会话的写入串行执行 |
| TUI 结束 | `session_shutdown` 触发定稿 |
| Web 结束 | 删除会话或关闭运行层时定稿；切换页面不结束实例 |
| 定稿 | 提问和轮次均为 0 时不产生记录；其余记录先写入各端点队列，再删除草稿 |
| 正常退出 | 等待定稿落盘，不等待网络响应 |
| 启动恢复 | 残留草稿按 `crash` 定稿；结束时刻取最后完成轮次，上下文条目数留空 |
| 恢复去重 | 沿用草稿中的 `recordId`，接收端按该字段去重 |
| 强制终止 | 没有完成轮次时无草稿可恢复；已有草稿只覆盖最后完成的轮次 |

开始与结束原因按通道取值：

| 通道 | 开始原因 | 结束原因 |
|---|---|---|
| TUI | `startup`、`new`、`resume`、`fork`、`reload` | `quit`、`new`、`resume`、`fork`、`reload`、`crash` |
| Web | `new`、`resume`、`fork` | `quit`、`delete`、`crash` |

## 队列与发送

每个端点独立保存最多 200 条记录，按 `recordId` 去重，超限时淘汰最旧记录。队列文件以端点 URL 的 SHA-256 命名；从配置移除端点时保留其队列，重新加入同一 URL 后可继续补发。

每批最多 50 条，记录正文合计不超过 900 KiB。单条序列化后超过 1 MiB 时不入队；超过发送预算的记录在发送时移除。限额不裁剪报错文本，超限按整条记录丢弃。

1. 会话开始、草稿恢复和定稿后触发发送。登录完成不单独触发，后续触发读取新凭据。
2. 同一 home、同一端点同时只有一个发送任务。不同端点分别发送和确认，一个端点失败不阻塞其他端点。
3. 进程内队列文件读写串行执行；网络请求不占用文件队列。多个 Pi 进程共用 home 时，文件更新仍可能互相覆盖。
4. 启动时将 `pending.jsonl` 中的记录复制到当前全部端点，再清除原记录；中断重试按 `recordId` 去重。
5. 队列替换失败时保留原文件。磁盘写入失败、容量淘汰、强制终止和退出时未完成的请求允许丢失。

上传协议见[接收端接口](../receiver/SPEC.md#接口)。单次请求超时为 5 秒。

| 结果 | 处理 |
|---|---|
| 202 | 从对应端点移除该批，其他端点不变 |
| 401 / 403 | 保留记录，停止本轮发送，等待后续触发读取有效凭据 |
| 400 / 413 | 丢弃该批，不自动重试 |
| 429 / 5xx / 网络错误 / 超时 | 保留记录，后续触发时重试 |
| 404 / 410 | 本进程停止向该端点发送，保留队列 |
| CA 缺失、无效或 TLS 验证失败 | 保留队列，不降低证书验证要求 |

采集、保存与发送失败均不向队员提示，不影响诊断。

## 凭据与配置

发送端被动读取 `auth.json` 中 CSTOA OAuth 的访问令牌及有效期，不刷新、不写回。记录不带身份字段，学号和设备归属由接收端通过 OA 内省取得。

`agent/home/telemetry.json`：

```json
{
  "enabled": true,
  "endpoints": [
    { "url": "https://www.cstoa.top/api/telemetry" },
    { "url": "https://8.163.28.9:8445/api/telemetry", "caFile": "timserver_1.crt" }
  ],
  "authProvider": "cstoa"
}
```

| 配置 | 规则 |
|---|---|
| `enabled=false` | 不累计、不写遥测文件、不上传、不探测管理员身份；重启生效 |
| `endpoints` | 公网必须使用 HTTPS；只允许本机测试使用 HTTP；禁止 URL 用户名、密码与片段 |
| `caFile` | 从遥测扩展目录读取，只用于该端点；校验证书链、有效期和主机名 |
| 币种 | 使用扩展目录中的 `currency.json`，规则见[契约](../../contract.md#计费币种) |
| Pi 自带遥测 | 与本扩展独立；工具包通过 `PI_OFFLINE=1` 和 `enableInstallTelemetry=false` 关闭 Pi 自带遥测 |

配置在启动时加载，修改后重启。发行取值由 `pack/release-settings.mjs` 维护，不复制本机凭据。
