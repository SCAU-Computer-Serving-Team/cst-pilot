# OA 登录与模型接入

状态：实现规格，尚未开发，整份等 OAuth 落地后再讨论。更新：2026-09-20。

OAuth 负责队员登录认证和接入团队模型服务。登录态随 U 盘保存，按令牌有效期延续。在 Web 中，OAuth 与 API KEY 共用模型服务的登录状态展示和退出操作；本文只规定 OAuth 的有效期和刷新。Web 接口见[模型与登录](../web/SPEC/app-router.md#模型与登录)。

## 范围与流程

1. 队员在 pi 执行 `/login`，选择 CSTOA OA。
2. Agent 申请设备码，按形态显示授权入口，见「登录形态」。
3. 队员在手机打开授权页（扫码或输入数字码），完成 OA 登录、TOTP 校验并确认设备与作用域。
4. Agent 轮询令牌端点，取得访问令牌，由 pi 保存到 U 盘的 `agent/home/auth.json`。
5. pi 携带访问令牌调用 OA 的 OpenAI 兼容代理。OA 校验权限与额度，转发到 New API 网关，记录用量。

模型调用链：`pi → OA 代理 → New API 网关 → 模型`。网关长期密钥只在服务端使用。

| 项 | 约定 |
|---|---|
| 授权协议 | OAuth 2.0 设备授权流，RFC 8628 |
| 授权主体 | 队员；机主不是 OA 用户 |
| 手机入口 | `https://cstoa.top/oauth/device` |
| 模型端点 | `https://cstoa.top/api/agent/llm/v1` |
| 模型权限 | `llm:chat`，按队员本人额度使用 |
| 用量归属 | 队员个人额度，标记为「维修」用途 |
| 授权界面 | 按形态显示，见「登录形态」；不自动打开机主浏览器 |

### 登录形态

两种形态共用同一套设备流与服务端批准逻辑，只有展示方式不同。

| 形态 | 展示 | 说明 |
|---|---|---|
| TUI | pi 原生设备码界面：网址与 6 位数字码 | 受终端限制，不自动打开机主浏览器 |
| Web UI | 登录面板渲染二维码，编码 `verification_uri_complete` | 手机扫码直达授权页并预填数字码；前端负责二维码与倒计时 |

扩展向 Web 层提供 `{ userCode, verificationUriComplete, expiresInSeconds, interval }`，Web 前端据此渲染。Web UI 尚未实现，本节先定接口形状。

上游 issue #9774（给 pi 原生设备码对话框加二维码）**只涉及 TUI**。Web UI 的二维码由本项目前端实现，不依赖上游。

## 登录有效期

| 模式 | 行为 |
|---|---|
| 默认 | 访问令牌有效期 2 小时，不下发刷新令牌；进入 pi 的刷新窗口后提示重新授权 |
| 记住 7 天 | 默认关闭。开启后下发刷新令牌；七天从首次授权起算，刷新不重新计时 |
| 更换电脑或盘符 | 沿用 U 盘凭据，不因换电脑额外要求登录 |
| 本地退出 | `/logout` 删除本地凭据 |
| 服务端吊销、改密 | 请求校验时拒绝既有令牌 |

开启「记住 7 天」时，授权页说明刷新令牌可能被期间使用过的维修电脑读取。

## 令牌与设备标识

| 数据 | 保存位置 | 有效期或用途 |
|---|---|---|
| `device.json` | U 盘 `agent/home/` | 首次生成设备标识，设备关联队员 |
| `device_code` | 设备授权过程中使用 | 5 分钟，使用、拒绝或过期后失效 |
| `user_code` | 授权页与终端显示 | 6 位数字，5 分钟；连续失败 5 次作废 |
| `access_token` | pi 的 `auth.json` | 2 小时；设备吊销或改密后失效 |
| `refresh_token` | pi 的 `auth.json`；服务端存哈希 | 可选，7 天；轮换、吊销或过期后失效 |

访问令牌用 HMAC 签名，复用 OA 的签名密钥。载荷如下：

| 字段 | 含义 |
|---|---|
| `mid` | 队员编号 |
| `typ` | 固定 `agent`，与其他 OA 凭据隔离 |
| `scope` | 已授权的作用域 |
| `device_id` | 设备标识 |
| `pv` | 密码版本 |
| `exp`、`jti` | 过期时间、令牌唯一编号 |

1. 请求校验包含签名、类型、作用域、有效期、设备状态与密码版本。
2. 刷新令牌每次轮换；检测到旧刷新令牌重放时吊销设备授权。
3. 作用域不超过队员本人权限，授权页完整展示；超范围的申请拒绝。
4. 其他 OA 业务按所需作用域复用登录身份，业务数据与传输规则由各自规格定义。

## 作用域

模型服务使用 `llm:chat`。其余作用域按独立业务需要申请，不作为登录或模型调用的必选权限。

| scope | 能力 | 权限来源 |
|---|---|---|
| `llm:chat` | 经 OA 代理调用模型，不向 agent 下发网关令牌 | 队员本人额度 |
| `task:read` | 读本人任务 | 队员本人 |
| `task:write` | 接取、到达、完成 | 队员本人，动作需确认 |
| `repair:write` | 提交修机日志 | 队员本人 |

1. 逐次授权，不默认全选；授权页完整展示申请的作用域，队员可见。
2. 增加作用域需要重新授权。
3. 申请超出队员权限时整单拒绝，不静默裁剪。

## 安全边界

| 风险 | 约束 |
|---|---|
| 机主系统不可信 | 按令牌可能被复制设计，限制有效期、权限与额度，并提供服务端吊销 |
| U 盘文件可能被复制或篡改 | `device.json` 只作标识，不证明请求来自原 U 盘 |
| Windows U 盘权限有限 | 不依赖 `0600` 保护凭据，尤其是 FAT/exFAT |
| 登录信息泄露 | OA 密码、TOTP 和确认操作在队员手机完成 |
| 凭据进入模型上下文 | 文件读取与检索工具排除凭据文件，日志不输出令牌 |
| 授权接口滥用 | 申请设备码按 IP 限流，令牌轮询遵循 interval，数字码限制尝试次数 |

TOTP 在本期实现绑定和校验，授权页强制校验；丢失后由管理员重置。

审计记录队员、设备、作用域、接口、结果、IP 与时间，保留 180 天。队员可在「我的设备」吊销授权，管理员可批量吊销。

## OA 接口

| 方法 | 路径 | 鉴权 | 功能 |
|---|---|---|---|
| POST | `/api/oauth/device_authorization` | 无，按 IP 限流 | 申请设备码 |
| GET | `/oauth/device` | OA 会话 | 手机授权页 |
| POST | `/api/oauth/device/decision` | 新登录与 TOTP | 确认或拒绝授权 |
| POST | `/api/oauth/token` | device_code 或 refresh_token | 换取或刷新访问令牌 |
| POST | `/api/oauth/revoke` | OA 会话或设备授权 | 吊销授权 |
| GET | `/api/agent/devices` | OA 会话 | 查询本人设备 |
| DELETE | `/api/agent/devices/{id}` | OA 会话 | 移除设备 |
| ANY | `/api/agent/llm/v1/*` | access_token | OpenAI 兼容模型代理 |

设备授权请求包含设备名、平台、Agent 版本和作用域。响应包含 `device_code`、`user_code`、`verification_uri`、`verification_uri_complete`、`expires_in=300`、`interval=5`。

轮询错误使用 RFC 8628 的 `authorization_pending`、`slow_down`、`expired_token`、`access_denied`。

## 本期验收

1. 新 U 盘完成手机授权后，权限与额度满足要求即可调用模型。
2. 未授权请求被拒绝；用量计入队员个人额度。
3. 默认模式不保存刷新令牌；记住模式由 pi 刷新并保存轮换后的凭据。
4. 同一 U 盘换电脑或盘符后，有效登录态继续使用。
5. 改密或服务端吊销后，旧令牌被拒绝；本地退出清除本地凭据。
6. 拒绝授权、超时、断网、权限不足和额度不足分别提示；不输出凭据。

## 当前约定

已定的部分，避免后续重复讨论。其余见正文。

| 编号 | 议题 | 决定 |
|---|---|---|
| D1 | TOTP 恢复方式 | 管理员重置，不设静态恢复码 |
| D2 | 记住 7 天默认值 | 默认关闭 |
| D3 | refresh 存储 | 明文存 U 盘 |
| D4 | 无单上门 | 不影响登录和模型调用；报修流程由独立业务定义 |
| D5 | 维修用量统计 | 挂个人额度并打「维修」标记 |
| D6 | 委员写操作确认 | 只对高风险动作确认 |
| D7 | 用户码格式 | 6 位数字 |
| D8 | 审计保留期 | 180 天 |
| D9 | 令牌签名密钥 | 复用 OA 现有密钥 |
| D10 | 任务关联 | 不与 OAuth 绑定，不作为登录或模型调用的前提 |
| D11 | 模型接入路径 | 方案 S：OA 提供 OpenAI 兼容代理，pi provider 指向 OA |
| D12 | 登录界面与二维码 | TUI 用 pi 原生设备码界面；Web UI 渲染二维码。上游 issue #9774 仅涉及 TUI |
| D13 | 手机确认时机 | 首次登录或需要重新授权时确认，不按修机任务触发；记住模式 7 天内免确认 |
| D14 | 凭据存储 | 只保留 pi 的 `auth.json` 一份；不建额外缓存 |
