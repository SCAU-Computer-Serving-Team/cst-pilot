# 产品规格

CST Pilot 是计算机维护队（CST）的便携式现场诊断 Agent。维修队员在机主电脑上从 U 盘启动本工具，通过只读诊断工具定位软硬件故障，并生成修复命令清单或执行受控的 BitLocker 操作。

## 诊断需求

诊断查询保持只读，不修改注册表、系统配置、服务状态或机主文件。工具行为与限制见 [diagnostics/SPEC.md](diagnostics/SPEC.md)，参数与返回字段见 [diagnostics/API.md](diagnostics/API.md)。

| 编号 | 需求 | 解决的问题 | 对应工具 |
|---|---|---|---|
| R1 | 进程盘点：CPU 与内存占用排行 | 哪些进程消耗资源 | `sys(proc)` |
| R2 | GPU 状态：每进程利用率与显存，独显附温度与功耗 | 显卡负载与显存占用 | `sys(gpu)` |
| R3 | 传感器：可读温度、风扇、电压与频率线索 | 是否存在过热或降频迹象 | `sys(sensor)` |
| R4 | 整机概况：CPU、内存、页面文件、内核池、机型与开机时长 | 整机基础负载与硬件背景 | `sys(overview)` |
| R5 | 开机自启盘点：注册表、启动文件夹、自启服务及禁用状态 | 开机自动拉起哪些程序 | `startup` |
| R6 | 事件日志查询：错误警告、开关机与蓝屏、崩溃、服务故障、磁盘与登录审计 | 过去发生过哪些系统异常 | `eventlog` |
| R7 | 设备与驱动状态：异常设备、核心硬件、外设与条件查找 | 设备识别与驱动是否正常 | `driver` |
| R8 | 存储分析：目录直接子项大小浏览、卷空间、物理盘、SMART 与目录占用排行 | 磁盘健康度与空间被谁占用 | `ls`、`disk` |

## 命令交付需求

常规修复由队员手动执行。模型通过 `command_plan` 保存和修订方案，队员核对后由 `runbook_deliver` 将指定版本导出至工具包 `outbox/<日期>/<ID>/`。`runbook` 支持单步生成纯文本清单。命令分档与编写规则由 [runbook SKILL](../agent/home/skills/runbook/SKILL.md) 约束。

| 编号 | 规则 |
|---|---|
| D1 | 单次调用产出一份清单，每条命令包含执行环境（`cmd` / `powershell`）、管理员要求、功能与影响说明、单行命令正文 |
| D2 | 清单写入 `outbox/<YYYY-MM-DD>/`，文件名带当天唯一递增序号与标题；传入已有序号时原地替换该份清单 |
| D3 | 命令按风险分为安全（`safe`）、较安全（`low`）、需与机主确认（`confirm`）三档，同档合并输出 |
| D4 | 仅生成 `.txt` 文件，编码为 UTF-8 BOM + CRLF；禁止生成 `.bat`、`.cmd`、`.ps1` 等可执行脚本 |
| D5 | 正文禁用 Markdown；文件头一行概括标题、风险档与时间，每条命令固定四行，命令正文独占一行且无前缀 |
| D6 | 每条命令写明功能与影响；不可逆或可能丢失数据的操作必须标明后果 |
| D7 | 功能相近的多条操作合并为一条单行命令 |
| D8 | 中高风险、不可逆且无退路的操作禁止写入任何清单 |
| D9 | 工具返回文件绝对路径、序号与条目数，模型向队员转述文件位置 |
| D10 | 写入失败（只读介质、空间不足、序号冲突）返回结构化错误，禁止静默失败或在 `outbox/` 外落盘 |

## BitLocker 执行需求

BitLocker 工具开放只读查询及受控的恢复密码解锁、完整解密能力。接口与安全细节见 [diagnostics/SPEC.md](diagnostics/SPEC.md#bitlocker状态解锁与解密)。

| 编号 | 规则 |
|---|---|
| B1 | `status` 实时查询全部可枚举卷或指定盘符，保留 Windows 原始状态码与采集错误 |
| B2 | `unlock` 使用 48 位恢复密码解锁指定卷，默认走 TUI / Web 独立隐藏输入通道；AI 填参路径须在本地确认传输边界 |
| B3 | `decrypt` 默认处理全部可枚举卷或指定盘符；在 TUI / Web 确认固定目标清单后逐卷发起后台解密，进度通过 `status` 复查 |
| B4 | 本地输入的恢复密码不进入模型上下文、会话记录、日志或遥测；AI 填参在落盘前脱敏；工具不自动清除系统卷自动解锁密钥或调用 `repair-bde` |

## UI 通道与 Web 需求

项目提供 TUI 与本机 Web 两个操作通道。运行协调见 [runtime/SPEC.md](runtime/SPEC.md)，Web 规格见 [web/SPEC.md](web/SPEC.md)，视觉规范见 [DESIGN.md](../DESIGN.md)。

| 通道 | 入口 | 定位 |
|---|---|---|
| TUI | 双击或命令行运行 `pi.cmd` | 默认启动通道；执行 `/web` 后转为待机宿主并停止接收终端输入 |
| Web | 在 TUI 中执行 `/web` | 本机回环浏览器界面，提供主页、聊天工作台、分支树、设置、登录与账号页 |

| 编号 | Web 需求 |
|---|---|
| W1 | 界面与动效按专用设计稿定制，随便携包分发预构建静态资源，现场无需安装运行时或执行构建 |
| W2 | 现代版支持 Chromium 111 起（Tailwind v4 + React 19）；面向 Chromium 86 的兼容版列入后续迭代 |
| W3 | 在项目开放能力范围内完整覆盖会话管理、模型与凭据配置，以及 `/new`、`/resume`、`/model`、`/tree`、`/settings`、`/login`、`/compact`、`/fork` 等操作 |
| W4 | 在同一 Pi 宿主进程内承载 Web 服务与多会话运行实例；TUI 释放已保存原会话后由 Web 接管，同一会话仅允许一个写入实例 |
| W5 | 支持浏览器真实地址、刷新、前进后退与多标签页；切换页面或关闭标签页不中断后台正在执行的会话 |
| W6 | TUI 与 Web 共用会话历史、模型目录与认证凭据；两端的界面主题独立保存、互不覆盖，Web 默认浅色 |

## 全局约束

- **支持环境**：Windows 10/11 x64。裁剪镜像、特殊介质与 Windows PE 按实际能力降级并明确报告错误。
- **零宿主安装**：仅使用随包分发的运行时与诊断组件（Pi、PowerShell、WizTree、LibreHardwareMonitor），不在机主系统安装运行环境或内核驱动。
- **管理员启动**：启动时统一通过 Windows UAC 请求管理员权限；取消或拒绝授权时直接退出。交互终端优先使用机主已安装的 Windows Terminal，不可用时回退系统控制台。
- **写入边界**：工具包内仅允许写入 `agent/home/`（凭据、设置、会话、收件箱、遥测队列）、`.state/`（运行状态）、`wiztree/tmp`（扫描临时 CSV）与 `outbox/`（命令清单）。
- **性能与输出**：常规诊断查询秒级返回；耗时目录扫描受预算或取消信号控制。所有工具输出结构化 JSON，区分业务数据、口径说明（`notice`）、部分降级（`degraded`）与整次错误（`isError`）。
