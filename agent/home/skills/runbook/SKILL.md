# runbook 工具说明

使用 `command_plan` 保存和修订手动修复方案，队员核对后由 `runbook_deliver` 导出 TXT。方案保存在 `agent/home/command-plans/`，文本保存在 `artifacts/<日期>/runbook/`，不执行任何命令，不改动机主系统。

## 唯一允许的用途

队员必须亲手执行的修复动作。典型场景：清理磁盘、卸载软件、关闭自启项、重装或移除驱动、重置网络配置。

诊断数据的采集一律走已有工具，不要写进清单。

## 风险分档

同一批、同一风险档的命令合并成一个方案。不同风险档分别保存，逐份核对后导出，明确执行顺序。

| 档 | `level` | 判据 | 例 |
|---|---|---|---|
| 安全 | `safe` | 只删系统可再生的缓存与临时数据；不动用户数据、不改配置、不需要管理员 | 清空 `%TEMP%`、清理 Windows 更新缓存、清空回收站 |
| 较安全 | `low` | 改可回退的配置或用户可见状态，影响范围明确 | 卸载用户自装软件、关闭开机自启项、重置网络栈 |
| 需确认 | `confirm` | 涉及机主个人数据或系统行为，动手前必须让机主知情同意 | 删除大文件或重复文件、禁用系统服务、删除系统还原点 |

**不进入任何清单**：不可逆且无退路的操作，以及可能破坏系统可用性的操作。例如格式化或 `diskpart clean`、改动引导、卸载系统关键驱动、批量删注册表项。这类操作只在对话里说明，由队员自行判断。

判据按操作的实际后果，不按命令的外形。同样是 `Remove-Item`，清 `%TEMP%` 是安全档，删用户文档是需确认档。

## 命令写法

1. **必须单行**。连接方式按解释器选择：PowerShell 可用 `;` 顺序执行，但前一步失败不会自动阻止后一步；cmd 用 `&&` 表示前一步成功后继续，`&` 表示继续执行。需要保证成功条件时，不用无条件连接符。
2. **同类合并**。清理多个目录写成一条带多个路径的命令，或用一次 `ForEach-Object`；不要为每个目录各写一条。
3. **不要合并不同目的的操作**。合并只针对同一类、同一影响的动作。
4. **不要写成脚本**。不要出现 `if` 分支、变量赋值、函数定义；队员需要看一眼就明白这条命令做什么。
5. **不加注释**。命令里不要写 `#`、`rem` 之类的说明文字，说明放在 `summary` 字段里。
6. **避免中文**。必须用到中文路径时保持引号完整，不要依赖代码页设置。
7. **不删用户数据**。清理类命令只针对系统缓存、临时目录和明确指定的垃圾文件。
8. **临时停止须安排恢复**。清理过程中临时停止服务或进程，应安排恢复；单行命令无法保证失败后恢复时，改为分步说明，由队员核查后执行。不要为不相关的操作停服务。

## 说明写法

`summary` 一句话，动词开头，同时讲清两件事：

- 做什么：动作和对象
- 有什么影响：占用释放、需要重启、可能报错、是否可恢复

不良示例：`建议清理临时文件`（没有影响、没说什么动作）、`释放空间`（没有对象）。

合格示例：`删除当前用户临时文件夹内容，释放 C 盘空间；使用中的临时文件可能报一次错，删除后不可恢复。`

## 环境字段

`shell` 只填 `cmd` 或 `powershell`，按命令的实际语法选。`admin` 默认 false，需要管理员权限的命令必须显式设 true，并在 `summary` 里写出「需要管理员权限」。

## 调用流程

1. 决定这批建议分几档，只保留能进清单的命令。每次新增或修改命令都调用 `command_plan`，包括后续追问；已有方案只代表它的对应版本。
2. 新方案传 `title`、`level`、完整 `items`，保存返回的 `runbookId` 和 `version`。前端从结果展示命令，不必在正文重复粘贴。
3. 说明命令的权限、主要影响和执行顺序，队员核对同意后调用 `runbook_deliver`，只传上述 ID 与版本。
4. 原样转述返回的 `file` 路径、版本、条目数与执行要点。文本在 `artifacts/<日期>/runbook/<ID>/` 中，按版本保存。
5. 文件是纯文本，双击只打开不执行；提醒队员逐条复制，不要整份运行。

## 修正已有清单

1. 调用 `command_plan`，传入原 `runbookId`、当前 `baseVersion` 和完整的新命令列表。ID 保持不变，成功后版本加一。
2. 出现版本冲突时，先读取 `agent/home/command-plans/<ID>/v<最新版本>.json` 核对内容，再修订。不要直接改版本号覆盖他人的命令。
3. 队员核对后导出最新版本。同版本重试沿用同一文件；已交付的旧版本保留原内容，过期版本无法再次导出。
4. 队员已执行旧版的一部分时，先说明本次改动和需要跳过的条目，避免重复执行。

## 单步交付

`runbook` 支持直接写出一份清单，参数为 `title`、`level`、`items`。文件按日期与递增 `sequence` 命名，修正这类文件时沿用其 `sequence`。多轮方案使用稳定 ID 与版本，不把 `sequence` 当作方案 ID。
